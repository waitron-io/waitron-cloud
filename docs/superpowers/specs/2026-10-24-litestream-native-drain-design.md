## Boundary and shutdown

Keep these events distinct: SDK request issuance, first-hop admission, independent storage-observer admission, validated runtime `/stop` acknowledgement, SIGTERM, observed child `close`, and passive transport idle. Record their order with one monotonic clock and a sequence number for ties. SDK log arrival is issuance evidence only; buffering can delay it. Never backdate the boundary to an idle callback, signal, or response finishing.

Enable the official private Unix control socket for the replicator. Send one `POST /stop` for the owned database, using the existing official request shape `{path, timeout: 2}`. Cap the response at 1,024 bytes. Require HTTP 200 and exactly `{status, path, txid}`, with `status === 'stopped'`, the exact owned database path, and a nonnegative safe-integer TXID (including 0). Reject unknown keys, malformed/missing/oversized replies, `already_stopped`, and child exit before acknowledgement. Keep the path and raw body private.

Start the existing **absolute 2,000 ms stop budget** before the control request. Validate its full reply, atomically mark the boundary, send SIGTERM, observe successful child close, and wait for remaining passive transport idle within that same deadline. Stop control therefore precedes the passive idle wait. Do not add a quiet period, retry, deadline reset or timeout increase. An interruption observed before the validated boundary stays a failure even if acknowledgement arrives later.

Keep SDK logs and both independent counters open through child close and settlement. A successful acknowledgement is neither process exit nor idle. A silent backend, missing close, remaining pending work at the deadline, generic active-close, invalid child output or nonzero exit still fails. Preserve the first reason, operation, event, counters and outcomes before destructive cleanup, then collect every owned resource even when evidence is refused.

## One bounded ledger

Use one session-owned ledger shared by the request audit, transport, observer and lifetime readers. It correlates each SDK invocation plus attempt ordinal privately. Both hops retain their own body measurements and outcomes; shared identity and timing do not make either hop's byte counter the other's evidence. Ordinary callers that omit the ledger remain strict.

Set **`afterStopAttemptCap = 3`**, fixed per replication session. Basis: the saved controlled probe shows two lists, and the existing genuine delayed-PUT fixture holds a successful storage reply for 1,500 ms. Allow room for those two lists plus one already-admitted upload completion. Three together have not been observed; this is a conservative design bound to qualify, not a measured historical maximum. At most one upload completion qualifies.

Count distinct affected SDK attempts once across all layers: storage admissions after acknowledgement, narrowly accepted post-ack list interruptions, and the one qualifying upload completion. These sets can overlap. Never reset the cap for retries, operations, phases or observers; the fourth affected attempt fails. An unpaired or unknown identity fails. A missing body fragment is retained as a gap, not a missing request identity.

| Observation | Classification and result |
| --- | --- |
| List issued before acknowledgement but held before storage observer admission until afterwards | A real after-stop admission; count that attempt. The saved initial held list belongs here. |
| List admitted by the storage observer before acknowledgement; successful response finishes afterwards | Ordinary request with a late response; do not call it an after-stop request or charge the cap merely for that response. |
| Known list's client-side response interruption first observed after validated acknowledgement | Retain `transport-error`, reason/event and observed bytes; count the affected attempt. Require the recorded `transfer-interrupted` / `response-pipeline` / `ERR_STREAM_UNABLE_TO_PIPE` signature, `clientClosed=true`, `responseHeadersSeen=true`, independent storage admission and no mutation. Admission timing remains separately truthful. |
| Same list interruption before acknowledgement, unknown event, upstream failure, or timeout | Fail. Later acknowledgement cannot forgive it. |
| Upload attempt admitted at both hops before acknowledgement, completing afterwards | Count once only if the entire request body reached storage and the actual backend acknowledged a successful commit for that same attempt. A lost client reply stays a transport error. |
| New PUT, upload retry, multipart operation, delete, GET, HEAD or any other operation admitted after acknowledgement | Fail. Permit only fresh list attempts and the exact already-underway PUT completion above; no new retry or mutation is authorized. |

Check first-hop admission too, so a new upload cannot claim an older SDK issuance as authority. A PUT held upstream of storage admission until after acknowledgement fails. A backend acknowledgement witness comes from the real storage response, including version identity where required, not a timer, request-body end, restored row count or inferred inventory entry. Uncommitted, partial and uncertain upload completion fails even if an earlier restore passed.

Keep the existing phase names. Do not call `setPhase` during active I/O, relax its pending-work guard, or reset a global phase midway through a request. Store immutable per-attempt phase/admission facts; after-stop classification is a separate dimension. Preserve all SDK attempts, retry ordinals, response status, outcomes, observed and attempted bytes, including when the permitted list response is incomplete. Record counter evidence even if lifetime completion rejects, so that a failure cannot erase bytes already observed.

## Evidence, output and recovery

Preserve the existing all-attempt snapshots and add a separate aggregate `afterStop` ledger to smoke output. It is a labelled subset of those totals, never an extra quantity to add again. Publish `cap`, `used`, `lateAdmissions`, `lateSettlements`, operation/retry/outcome rows, separate producer/observer bytes, actual reconciliation result and closed gap/reason categories. Admission and settlement counts may overlap; `used` is their distinct-attempt union. Keep invocation IDs, paths, headers, raw logs and unknown fields out of output. Validate the output's closed schema before export.

When the ledger is nonempty, publish `costAccuracy: {status: 'incomplete', reason: 'after-stop', message: 'Cost may be a few requests short after stop.'}`; omit this caveat when empty. Preserve request reconciliation only when identity evidence really pairs; preserve body reconciliation only when both independent observations actually agree. Otherwise retain discrepancies, `unknown` status and the incomplete evidence. Never turn an interrupted attempt into success or manufacture billable quantities. With an empty ledger, retain exact ordinary-mode accounting and existing unknown evidence refusals.

List interruption cannot alter stored objects. Lifetime readers may settle that specific read's pending token under the ledger contract, while still requiring independent final inventory verification. PUT lifetimes require the real commit witness and retain time bounds and every version. Do not replace missing commit evidence with an inventory guess or apply a blanket `!interrupted` bypass. Unrelated writes, deletes, multipart, inventory ambiguity and privacy violations continue to poison the session.

After stop, child exit and transport settlement, restore from the **final storage state**, then verify every sale and SQLite integrity. Move the existing restore loop to this final position; keep its total **12 attempts** and **1,000 ms** waits without resetting or adding another loop. Retain any earlier readiness evidence without treating it as final recovery proof. Preserve both sale writes, fiscal verification, injected failure and retry, independent administration accounting, all inventory/version/storage bounds, security/isolation and owned cleanup checks. An interrupted upload that loses data fails.
