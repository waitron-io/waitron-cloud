# Verified merge CI: D571 part 5

You should not wait for product checks that already passed on the exact files you merged. An identical-tree merge records verified PR evidence instead. A different tree uses the existing PR selectors on the actual main push range. Missing or contradictory evidence runs more work.

## Decision and interfaces

Use Node's existing test runner and `gh api`; add no service or dependency. Keep focused responsibilities: `ci-workspace-snapshot.mjs` supplies immutable package/source/test data; `ci-range.mjs` resolves trusted revisions; `ci-plan.mjs` selects work; `ci-evidence.mjs` validates/records plans and job contracts; `ci-reuse.mjs` verifies evidence; `ci-reuse-api.mjs` supplies bounded GitHub reads. These are proposed interfaces, not implementation bodies:

- `resolveRange(event, context, git) -> {kind:'pr'|'push'|'full', base?, head, reason}`. Context includes real `eventName`, `ref`, `sha`, `repository`, `runId`, `full` and `called`.
- `loadWorkspaceAtRevision(head, git) -> {revision, packages, testFilesByPackage}` reads tracked workspace patterns, package manifests, dependency source and test inventories as Git data. `selectPlan({base,head}, snapshot, git) -> Plan` requires `snapshot.revision === head` and applies today's PR selection to those inputs; `workPlan` receives the saved test inventory rather than reading the current directory. The reviewed selector never discovers historical inputs with current-directory `pnpm ls` or source reads. `createPlan(event,context,workspace,git,api)` retains its entry point and selects the range before considering reuse.
- `findReuse(context, {api,git,now}, workflowPath) -> {reuse:ReuseProof|null, reason:string}` keeps the existing synchronous planner boundary, with bounded synchronous reads; `assertSourceEvidence(source, selection, jobs, contract)` rejects incomplete evidence.
- `expectedJobContract(workflowPath, selection) -> {required:string[], skipped:string[]}` derives exact display identities from reviewed workflow definitions and matrix builders. Export the existing CI allocation validation for both this contract and the strict summary. Unknown workflow structures refuse reuse.

The API seam returns raw validated data, without converting missing fields into defaults:

| Read | Required data transfer object |
| --- | --- |
| Repository/workflow | numeric repository ID, full name, default branch; numeric workflow ID, exact path, active state |
| PR | number, state, merged_at, merge_commit_sha; base/head `{sha,ref,repo:{id,full_name}}` |
| Commit | requested `sha`, `tree.sha`, parent SHAs |
| Run/attempt | id, workflow_id, path, event, repository/head_repository IDs and names, head_sha, head_branch, run_attempt, status, conclusion, optional PR associations, referenced_workflows |
| Job | id, run_id, run_attempt, head_sha, name, status, conclusion |
| Page | items, total_count where supplied, next-page identity, terminal-page proof |
| Artifact | id, name, expired, size, digest, workflow_run identity; bounded JSON bytes |

`PlanEvidence` version 1 contains repository ID/name, PR number, original event base/head/merge-base SHAs and PR identity, checked-out head/tree, `github.workflow_ref`/`github.workflow_sha` and event `GITHUB_SHA`, workflow ID/path/execution SHA, run ID/attempt, selection, and a SHA-256 digest of canonical selection JSON. Upload exactly one `ci-plan-v1-<workflow-key>-<runId>-<attempt>` artifact, one JSON file, maximum 256 KiB, retained 14 days. Validate metadata, archive entries and digest; never extract arbitrary paths or execute its contents.

`ReuseProof` is `{version:1, repository, repositoryId, pr, mergeSha, sha, tree, workflowId, workflowPath, runId, attempt, planDigest, jobsDigest}`. CI stores it in `plan.reuse`; sibling decisions carry their own proof. Reused CI has empty package/receipt arrays, `typecheck:false`, no documentation/scripts work, and successful current planner/summary jobs. Existing matrix/output booleans remain; add `mode` (`reused`, `selected`, `full`, or sibling `unselected`) and bounded reason. Write the full decision to an artifact and linked step summary. The old two-field proof is invalid.

## Source qualification

1. Admit only a real, non-forced push to `refs/heads/main` in `waitron-io/waitron-cloud`. Validate current run/repository/workflow identities. Require exactly one associated closed, merged PR, matching merge SHA and main base in that repository, with a same-repository head. For reuse, require one pushed commit whose sole parent equals event `before`; other valid push shapes still get range selection.
2. Fetch both commits by exact SHA. Each response must name that SHA; both valid, nonzero tree IDs must agree with local Git and each other. The verified commit is the checked-out PR head, not GitHub's temporary PR merge commit or a branch name.
3. List all exact-head PR runs for this workflow. Select the newest run by ID **before** examining success; take its latest attempt. A newer red, pending or cancelled run defeats an older green one. Validate event, workflow ID/path, repository/head repository, head SHA/branch. Cross-check any retained PR association, but do not require this optional API field. No fallback to an older run or attempt.
4. Require the attempt-bound plan artifact and independently reconstruct its selection using the currently reviewed selector on the original immutable revisions. Read historical files as data through Git; never import historical modules, install them, run their planner, or execute downloaded source. The original base/head come from the event fields preserved by the reviewed emitter in that attempt-bound artifact. Bind its PR number/head to the unique merged PR and the exact source run. Independently fetch the recorded commits, verify their identities and ancestry, recompute merge-base and load the head-bound workspace snapshot before comparing canonical plans. Do not depend on the source run's optional `pull_requests` list or guess from today's mutable PR base: actual merged run `41978702284` returns an empty list. This trust boundary is explicit: GitHub binds the immutable artifact to the exact successful attempt, and the reviewed workflow/emitter binds its captured original event fields; a JSON digest alone does not establish that provenance.
5. Prove workflow provenance separately from the checkout. Fetch the recorded `github.workflow_sha` and event execution commit by exact SHA, verify the original PR merge topology against the saved base/head, and compare the workflow plus every local reusable/action definition at that execution revision, source head and current tree. Require identical reviewed definitions, approved exact-head checkout rules, matching `workflow_ref` repository/path and resolved references for called workflows. The workflow ID/path and attempt-bound artifact metadata must agree with GitHub. The artifact's self-declared digest or base SHA alone grants no permission. A mismatch or unavailable execution commit takes full work. Require the selector/emitter/contract import closure at source head to match the reviewed current versions. This deliberately makes bootstrap and unsupported historical runs ineligible.
6. Page through the exact-attempt jobs. Require unique positive job IDs and unique exact expected names, matching run/attempt/head, completed status, every required identity successful and every known unselected identity skipped. CI requires `changes`, `summary`, and each selected root shard, typecheck, package row, receipts, documentation or scripts job. Source summary must actually finish successfully; the current-run publication exception cannot qualify a source. Unknown jobs, omitted shards, failed optional-looking jobs, missing skipped identities and duplicate placeholders refuse reuse. Do not accept total run success as proof.
7. Re-read the source run and newest-run listing after jobs/artifact reads; identity, latest ID, attempt, status and success must remain unchanged. The current summary repeats source qualification before accepting skipped work. Later source changes invalidate operator readback; receipts describe a point-in-time proof, not a promise about future reruns.

A docs source is valid when both immutable audits qualify, the document check passed and the other families were explicitly unselected. A scripts/scoped source similarly needs its exact selected work and justified skips. An empty or malformed source plan is **invalid evidence**, not legitimate unselected work. Valid cost/venue `required:false` needs the reviewed selector's nonempty input range and successful planner/summary, with the known proof jobs skipped. Never demand every product suite from these scoped PR sources.

The adapter follows pagination for associations, runs, jobs and artifacts: 100 items/page, at most five pages/list, 30 requests and 30 seconds total per verification, each API command at most five seconds and each Git read bounded by remaining time. Check totals, terminal pages, duplicate IDs and changing listings; API search limits, truncation or budget exhaustion never grant reuse. Do not poll for green. Evidence refusal selects full work for that workflow. A proven unequal tree goes directly to range selection; invalid range or uncertain source evidence goes full. Unexpected planner failure fails the planner; it cannot publish skip permission. Keep existing two-minute planner/summary limits and the summary's 60-second publication deadline.

## Actual changed range and independent workflows

For PRs, keep merge-base to exact head. For main pushes, validate `event.after == context.sha`, both nonzero lowercase 40-hex commit SHAs, exact commit resolution and `git merge-base --is-ancestor before after`. Diff **before to after**, with NUL paths and `--no-renames`, across every pushed commit. Never substitute `after^`, PR merge-base or `event.commits` paths. Direct/multi-commit pushes select from that whole range; forced/deleted/new-branch, malformed, missing/non-ancestor or empty ranges run full. Reuse refusal caused by uncertain evidence also runs full. Call the common selector directly, without constructing a fake pull-request event.

That selector retains audited Markdown, mixed prose, package/revision/lock readers, root-script plans and receipt selection. Unknown inputs and stale evidence retain existing full work. Audit v2's policy is frozen and its records are per-path: review changed readers, renew only owning docs records; never renew identity/gateway/lock peers merely to recover selection.

| Workflow | Independent source and fallback |
| --- | --- |
| CI | Exact `ci.yml` PR plan and strict job contract; otherwise common range selection or full on uncertainty |
| AWS | Own `aws-infrastructure.yml` PR run; all four `verify` cells (guards-1/2/3, suites) required; otherwise existing four-cell verification |
| Cost / venue | Each own PR run and native matrix/selection. Integrate H part 4's `proofInputPlan` through a real range interface, preserving its conservative fallback; never infer these from CI receipts or CI reuse |
| Download diagnostic | When its existing main path trigger fires, use its own PR run and `linux-contention` evidence through the same contract; preserve the bounded 32-case command and triggers |

Add lightweight decision/evidence and always-running strict summary jobs where siblings lack them. Reuse skips their product jobs; a missing source runs that workflow's normal work. Cost's existing docs-only main trigger exclusion can mean **no run**, justified by the exact trigger and diff, not by borrowed evidence. Keep all workflow decisions independent so one refusal does not repeat other proven workflows.

Schedule, workflow_dispatch, workflow_call and `full:true` always force full before examining payloads or reuse. Reusable workflows inherit the caller event name. Pass `toJSON(inputs)` as `CI_WORKFLOW_INPUTS`; presence of the declared `full` key marks a call and forces full even when its value is false. Direct PR/push inputs lack that key. Keep explicit `full:true` call sites and a default-true call input; do not rely on `eventName == workflow_call`. Coordinate with H part 6's `nightly.yml` (`17 3 * * *`, standard/cost/venue calls and prefixed summary). Its inspected candidate does not call AWS: add an AWS full reusable call and include it in nightly-summary before enabling AWS reuse. Preserve nightly alerts, manual rehearsal, all checks and deadlines. No provider deployment or resources are involved.

## Operator readback and watcher checklist

Before runtime landing, send this checklist to the watcher for all six Cloud runbooks, and retain the watcher's completion receipt. This planning invocation does not write campaign files.

- For every merge, record exact merge SHA/tree and main run IDs for each triggered workflow, including AWS and applicable diagnostics. Enumerate complete attempt jobs with `gh api --paginate --slurp repos/waitron-io/waitron-cloud/actions/runs/<id>/attempts/<attempt>/jobs?per_page=100`; read final logs, counts, named optional skips and checkout SHAs. A queued, missing, cancelled or red required result keeps H12 open.
- For **reused** work, download the main decision and source-plan artifacts. Run proposed `node scripts/ci-evidence.mjs --readback <decision.json>`: it independently repeats source qualification and current strict-summary validation and exits nonzero on refusal. Record repository, PR, merge/head/tree, workflow/path, source run link/attempt, plan/jobs digests, actual selected successes and justified source skips. Main planner/summary must pass; product jobs must be explicitly skipped for reuse. Record source test counts as inherited, with zero newly executed product checks. Check each sibling against its own source.
- For **selected changed-tree** work, use the same readback command to recompute the literal before..after plan, compare the decision, run the strict summary against every final job and verify each execution checked out `after`. Record selected packages/shards, receipts, docs/scripts work and explicit unselected families; full fallback records its reason and complete inventory. Empty scope never qualifies.
- For a trigger-excluded workflow, record `not-triggered`, exact workflow revision and matching path proof. For a present but unselected cost/venue workflow, require its successful decision/summary and justified skipped matrix. These are different outcomes from missing evidence.
- Keep nightly H12 separate: scheduled/called/manual full runs must execute all required work and the nightly summary, with no reuse. Verify PR #942 and AWS inclusion are on main. Retain current-head every-job qualification, normal hooks, own H11 lock, signed squash, main install and only-owned cleanup.

Implementation risks remain: GitHub may stop serving a recorded temporary merge commit; artifact retention may expire; reusable-job skipped names and resolved workflow metadata need exact hosted fixtures. These conditions refuse reuse. A single bounded scratch proof may settle API shape uncertainty if local fixtures cannot: use an owned temporary branch/draft PR, no deployment, provider resource or new spending, and clean only owned refs. Workflow edits without matching execution-definition proof take fallback; the next unchanged-workflow PR proves reuse. Do not claim runtime savings until that readback succeeds.
