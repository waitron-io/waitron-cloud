# Paid venue email signing in Cloud · slice 2b

In local tests, an operator can run `venue-mail:signing <venue-id>` to set up, check or retire signing for a saved test venue. Rerun after DNS or Amazon Simple Email Service (SES) updates. The portal still checks DNS delegation, and staff mail uses the Waitron sender. [Cloud plan](2026-11-25-paid-venue-email-cloud.md#2b-show-verified-domain-records) · [Domain records plan](2026-11-25-paid-venue-email-domain-records.md)

1. Add `venue-mail-signing{,-cli}.ts` and a package script in `packages/remote-access`. Follow the registration cleanup command's one-shot pattern. Reuse `readVenuePermissions`, the active-installation check in `account-http/src/venue-email.ts` and the bounded CNAME lookup. Before claiming a domain, require and recheck the current Connected or Hosted test choice and its exact alias to `<selector>.mail.<suffix>`.
2. Append registration migration `089_venue_mail_signing.sql` in `migrate.ts`. Keep one row per venue and a unique normalised domain in the provider scope. Store organisation, selector, public key, scope, creation tag and pending operation so cleanup survives reset, transfer and process exit. Serialise with a PostgreSQL session lock in the one owning database. Commit the pending operation before each bounded provider write and stop writing if the lock connection dies. Keep provider calls outside venue transactions.
3. Add `ses-signing.ts`, SES and caller-identity SDK dependencies, and the generated lockfile. Document `CLOUD_VENUE_MAIL_{TEST_ACCOUNT_ID,SES_REGION,DNS_ZONE_ID,TEST_DOMAINS}` in `.env.example`. Check the AWS account using the SES credentials. Require the configured Route 53 zone to serve `CLOUD_VENUE_MAIL_DNS_SUFFIX` and the command to be the only writer for the allowlisted identities. Save a fresh 2048-bit RSA public key and tag before creating the exact SES identity with the selector and in-memory private key. After matching SES readback, use mail-only Route 53 `CREATE` in `route53-dns.ts` to publish one TXT value with quoted chunks of at most 255 characters. Preserve certificate rules.
4. Extend `dns-lookup.ts` with bounded TXT resolution. Verify the exact alias and public key, the SES tag and selector, enabled external signing, DKIM `SUCCESS` and SES sending verification. Recheck the current organisation, address, selector and paid installation before reporting verified. Mailbox edits on the same domain reuse the key. Require exact identity proof here and in 2c, even when SES inherits permission from a parent domain. [SES identity rules](https://docs.aws.amazon.com/ses/latest/dg/creating-identities.html) · [Identity read](https://docs.aws.amazon.com/ses/latest/APIReference-V2/API_GetEmailIdentity.html)
5. Read back SES and the Route 53 record set after timeouts or already-exists replies. Resume on a match, hold inconclusive claims for operator reconciliation and retry definite rejections after fresh checks. Turn off automatic write retries. Add a read-only `--stale` list of claims whose venue, choice or paid eligibility no longer matches. Rerun by venue to retire them. Recheck the SES tag before deleting, then confirm SES absence and delete only the saved TXT value. Confirm its removal before releasing the claim. Leave foreign records alone. For `--rotate`, retain the claim, selector and alias while retiring the old identity and TXT. A later run creates the replacement and verifies it afresh. Signing is unavailable between the two. Slice 2c accounts for fallback and any identity settings it adds.
