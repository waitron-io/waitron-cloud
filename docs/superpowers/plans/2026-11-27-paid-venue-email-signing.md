# Paid venue email signing in Cloud · slice 2b

A Cloud operator can run `venue-mail:signing <venue-id>` to set up, check or retire signing for a saved test venue. Rerun it after DNS or Amazon Simple Email Service (SES) updates. The command reports verified for the current choice and leaves the portal's DNS tick in place. Staff email still uses the Waitron sender. One command keeps provider calls out of portal requests and mail delivery. [Cloud plan](2026-11-25-paid-venue-email-cloud.md#2b-show-verified-domain-records) · [Domain records plan](2026-11-25-paid-venue-email-domain-records.md)

1. Add `venue-mail-signing{,-cli}.ts` and a package script in `packages/remote-access`. Follow the registration cleanup command's one-shot pattern. Reuse `readVenuePermissions`, the active-installation check in `account-http/src/venue-email.ts` and the bounded lookup in `remote-access/src/dns-lookup.ts`. Require a saved Connected or Hosted test choice and the exact alias to its target under `CLOUD_VENUE_MAIL_DNS_SUFFIX` before claiming the domain. Recheck the choice after DNS.
2. Append registration migration `089_venue_mail_signing.sql` and register it in `migrate.ts`. Keep one row per venue and a unique normalised domain within the configured provider scope. Store the organisation, venue, selector, public key, provider scope, creation tag and pending operation so cleanup survives reset, transfer and process exit. Use a PostgreSQL session lock to serialise signing commands in the one database for this test SES account and region. Commit each pending operation before writing to a provider. Keep provider calls outside the venue transactions.
3. Add `ses-signing.ts`, the SDK dependencies and lockfile. Check the expected test AWS account with the same credentials, pin the region and zone, and allow only configured test domains for which this command is the sole writer. Generate a 2048-bit RSA key. Save its public half and a unique tag before creating the SES identity with the saved selector and private half. Keep the private half in memory. Publish the public half once SES confirms the tag. Add a mail-only operation in `route53-dns.ts` to create the exact target TXT as one value with quoted chunks of at most 255 characters, and delete that value. Keep certificate rules. Verify the exact alias and TXT, ownership tag, exact SES selector, enabled external signing, DKIM `SUCCESS` and SES verification for sending. Recheck organisation, current address, selector and paid installation before reporting verified. Mailbox edits within one domain reuse the key. [SES identity read](https://docs.aws.amazon.com/ses/latest/APIReference-V2/API_GetEmailIdentity.html) · [SES creation](https://docs.aws.amazon.com/ses/latest/APIReference-V2/API_CreateEmailIdentity.html) · [Route 53 TXT format](https://docs.aws.amazon.com/Route53/latest/DeveloperGuide/ResourceRecordTypes.html#TXTFormat)
4. Bound provider calls and turn off automatic write retries. After an interrupted write, resume on matching provider readback. Hold the claim for operator reconciliation if readback is inconclusive. Retry definite rejections after fresh checks. After reset, transfer, domain change, loss of eligibility or explicit `--rotate`, confirm the tag before deleting by domain, confirm SES absence, then delete only the saved TXT and confirm its removal. Release the claim after cleanup. Rotation keeps the claim and the venue alias through replacement. Rerun to provision a fresh key and require new verification. Leave foreign resources alone.
