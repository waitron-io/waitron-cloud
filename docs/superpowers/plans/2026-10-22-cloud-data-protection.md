# Cloud data protection implementation plan

> **For agentic workers:** Execute inline/native using `superpowers:executing-plans` after separate build authority. No automatic per-task agents. Read the approved spec alongside this roadmap; do not implement from this publication alone.

**Goal:** Build Cloud's country, access, return and deletion controls without changing application fiscal authority or enabling unqualified services.

**Architecture:** Start with a SQL-free outbound AI refusal boundary and synthetic local proof. Then add the service register, country policy, durable venue decisions and narrowly scoped adapters in separately landable slices. Keep outside-call intent and uncertain outcomes in PostgreSQL; Waitron remains responsible for application stop, capture, restore and activation.

**Spec:** [D101](../specs/2026-10-22-cloud-data-protection-design.md), approved from PR283, `9701cd2359d69f0a3e8960b761754cf492aac745`, on 2026-10-22 around 08:30 **for build planning only**. ## Global constraints and stop boundaries

- One venue approval keeps support access open for **at most 24 hours**, shorter where practical; extension requires fresh approval. It is a maximum, not a default entitlement.
- Spain venue data, logs and KMS keys stay in `eu-south-2`; the extra encrypted backup destination is **Paris `eu-west-3`**, subject to service, contract and recovery qualification. No automatic runtime failover, key replication or Spain-outage recovery promise.

## Review focus

Each case has a named assertion in the owning slice, in addition to the full section 8 matrix below.

1. A caller sets a regional URL, a global default or a fake enable flag: AI still sends zero requests, including review/retry and maintained trial tools (slice 1). Frozen experiments remain preserved and outside supported execution.
2. A policy or lifecycle revision changes while credentials are being issued: no stale credential, placement or object becomes visible; reconcile any already issued authority (slices 4–5, 9).
3. Revocation arrives during streaming/decrypt or after an external command was accepted: stop new release, show pending cancellation, reconcile the accepted effect without replay (slices 6–7).
4. Delete/resubscribe races the exact UTC deadline across restart or a lost provider reply: one durable outcome, no deadline extension or resurrection (slices 4, 9–10).
5. The freshest backup is unverified, its old key remains needed, or an extra-region/shared copy survives: show truthful recovery/deletion status; preserve dependencies and other venues (slices 7–10).
