# D643 public customer menu implementation plan

On a test installation, a customer on mobile data can open a published, read-only menu on the venue’s assigned or custom HTTPS name. After the manager switches it off, a fresh request gets 404 within a minute. Connected and Hosted venues qualify, including trials. The [joint design](https://github.com/clintongormley/waitron/blob/bd5d2dbf1976ede08efc2ebaf0e01b9063aaf884/docs/superpowers/specs/2026-11-25-customer-menu-public-access.md) defines the Cloud and Waitron contract. The watcher cleared that design at 15:24 on 25 November. Keep ordering and production enablement outside this plan.

## 1. Gate, cache and limits

After watcher clearance, start with a synthetic TLS box in `packages/remote-access/test/public-gate.test.ts`. Make each focused test fail before changing `packages/remote-access/src/public-gate.ts`, then rerun it. Reuse signed routes and host/TLS name matching. Forward GET and HEAD on the agreed menu paths only, to port 8443 on the route’s tunnel address, using its staff hostname for Host and certificate verification. Allow framing on published menu pages and keep visits, embeds and previews cookie-free. Return 404 for off, missing, blocked or ineligible menus, 503 when the box or authority is unavailable, and 429 under load.

Ask the account service for current eligibility and the durable venue block on every request, including cache hits. Add a bounded, unexposed listener on the test Compose network and wire it through `gateway-cli.ts`, `deploy/test-cloud/account-worker.mjs`, `runtime.mjs` and `compose.yaml`. Reuse `readGuestMenuRelease` in `packages/remote-access/src/guest-menu.ts`. The signed route supplies the venue ID. Check that the route is still current before replying. The hosted copy’s `off` state only describes the copy. Keep the owner check and test switch, and cover trial and block admission in `packages/remote-access/test/guest-menu.test.ts`.

Start at 120 requests per source per minute, 16 in flight, five seconds total and 2 MiB per response. Cache successful pages and data by venue, current route, public host and language URL, up to 64 entries and 8 MiB. Honour upstream freshness and age within a 60-second total lifetime. HEAD can read the cache without filling it. Content-named assets keep their longer browser lifetime. Keep customer counts separate and source addresses out of logs. Since the HAProxy public-host byte counters feed trial usage, refuse menu enablement with signed traffic metering active. The first paired test uses the unmetered test gateway. Estimate 230 code and 160 test lines, under three hours to open the pull request once the contract is ready.
