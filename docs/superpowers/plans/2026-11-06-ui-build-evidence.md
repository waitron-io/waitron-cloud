## Inventory and interfaces

Create `scripts/release/ui-build-inputs.mjs` for immutable reads/classification/hashing, `ui-build-policy.json` for reviewed supported recipes, `ui-build-source.mjs` for owned materialisation/process lifecycle, and `ui-build.mjs` for reservation matching/F preparation/recording. Create matching `ui-build-inputs.test.mjs`, `ui-build-source.test.mjs`, `ui-build.test.mjs` and shared real-Git fixture helpers in `ui-build-fixtures.mjs`. Extend `docs/shared-ui-release-ledger.md` and D579 status only with delivered behaviour. Do not wire `.github/workflows/ui-release.yml` in this slice.

`computeUiBuildEvidence({sourceRepo,source,recipeRepo,recipeCommit,tools,sourceChecks}) -> Promise<Evidence>` reads actual objects/tools. `source` is the existing `{repository,commit,version}`; Cloud repository is `waitron-io/waitron-cloud`, `recipeCommit` is full 40-hex, `tools` maps `{node,pnpm,npm,git,tar,sh}` to `{executable,distributionRoot}` with trusted absolute paths, and `sourceChecks` is a bounded opaque Buffer. `Evidence` contains `{schema:1,source,recipeCommit,inputs,recipeInputs,toolchain,inputsSha512,recipeSha512,sourceChecksSha512}`. It returns computed values, never accepts expected digests as proof. Export `readUiGitTree({repo,commit,git}) -> Promise<{commitBytes,trees,files}>` for Task 2: `trees` maps object ID to Buffer; `files` maps path to `{mode,objectId,bytes}`. All returned objects have passed hash/type/path checks.

Each inventory entry is a fixed tuple `[role,path,gitMode,byteLength,sha512]`; tools use logical relative paths and mode/length/content too. Use roles `build`, `check-definition`, `context`, `recipe`, `tool`; sort by role then UTF-8 path bytes, reject duplicate tuples/paths, and serialise fixed-order tuples as UTF-8 `JSON.stringify(value) + '\n'`, with no locale sort or object-key order dependence. Hash `['ui-build-evidence',1,'inputs',source.repository,source.commit,source.version,entries]`; recipe hash uses `['ui-build-evidence',1,'recipe','waitron-io/waitron-cloud',recipeCommit,source.commit,policyVersion,commands,toolchain,recipeEntries]`. Commands are ordered `[tool,cwdRole,args,envTuples]` with sorted environment pairs and owned paths represented by roles. Toolchain is an array `[name,version,os,arch,entries]` sorted by tool name; use no free-form objects in either hash preimage. Include the source lock hash in both domains and F's script in recipe entries.

Cap each repository at 50,000 entries, each blob at 16 MiB, cumulative source/recipe bytes at 512 MiB, serialised inventory at 32 MiB, source-check bytes at 16 MiB, and each tool distribution at 256 MiB/20,000 files. Count streaming input before allocation; reject malformed UTF-8 in paths/JSON (binary blobs stay bytes), truncation, unknown schema/fields/roles, unsafe integers, escaping paths and nonregular tool files except explicitly resolved internal installation links. Hash source-check Buffer bytes directly for comparison only: a matching `sourceChecksSha512` does not authenticate supplied CI evidence.

F's `preparation.json` stays its existing format: `inputs` are per-file hashes over F's listed Git paths, `recipeSha512` hashes only its own script, and `toolchain` has three versions. Recompute and compare that receipt's exact key set and values from the immutable source/F script and actual archive/toolchain. Cloud's versioned combined recipe digest is distinct; never compare F's single-file digest to the ledger's Cloud digest or silently reinterpret an existing reservation.

`withUiBuildSource({sourceRepo,sourceCommit,tools,limits}, use) -> Promise<T>` calls `use({checkout,output,home,scratch,store,env,run})` inside owned distinct directories and cleans up afterwards. `buildReservedUi({ledger,sourceRepo,recipeRepo,recipeCommit,tools,sourceChecks,at,limits}) -> Promise<{evidence,preparation,archive,nextLedger}>` returns an archive Buffer and validated ledger, leaving input files unchanged. Accept only active `reserved` or `prepared`; compare all three computed evidence hashes and exact source/version before calling any source install/build/preparation command. Verify the executing Cloud module/import closure against `recipeCommit` too; refuse dirty or unchecked recipe code rather than hashing a commit while executing other bytes. The ledger stores the recipe digest, not `recipeCommit` or the complete evidence. Before reservation, the caller durably retains `Evidence`, the exact `sourceChecks` bytes, and the verified recipe/toolchain material needed for recovery, under the reservation digests. Missing retained material stops recovery. Recovery executes the retained, verified recipe commit and toolchain; a later Cloud commit must not silently change the reserved digest. Production retention wiring remains caller orchestration work. Reject uploading/published/empty ledgers first. `limits` may shorten, never raise, the fixed bounds below.
