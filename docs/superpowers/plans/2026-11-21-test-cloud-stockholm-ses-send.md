# Switch the hosted test Cloud to Stockholm mail for one mailbox

The owner said “yes to the trial” on 19 November at 19:20 (campaign desk record `20261119-1848-K-amazon-email-trial.md`). On 21 November at 14:02 the watcher directed Lane K to switch the existing hosted test Cloud and send its first real email to the owner's verified mailbox. This replaces the isolated-run proposal and follows the [19 November plan](2026-11-19-test-cloud-amazon-ses.md).

1. **Normal startup.** Add `deploy/test-cloud/compose.amazon-ses.yaml` after the Amazon overlay. In `scripts/test-cloud-deploy.mjs` accept one explicit Amazon `up` option for the SES settings, with the enable flag and one fixed read-only mount on the email worker only. `deploy/test-cloud/ses-runtime.mjs` reads one bounded, regular mode-0600 file without following symlinks. Load it from `email-worker.mjs` only with the explicit flag on the approved test origin. Basic startup uses Mailpit. An invalid enabled configuration stops the worker with a fixed diagnostic. Keep secrets out of Compose environment and logs.
2. **Authority and keys.** In `ses-runtime.mjs` pin a fingerprint of the exact sandbox scope after independent watcher readback. Canonicalise the mailbox, region, country, sender, test origin, policy and binding revisions, IAM user and provider resource names. Verify the pin before constructing the test-only policy for `validateSesFeedbackConfig`, with evidence tied to the sandbox decision and readback. Create and retain a separate recipient key set in the private settings. Use `createSmtpAccountMailer` and the existing sender and TLS restrictions. Narrow the existing SMTP user's grant to the verified mailbox and issue its one credential through the temporary provisioner. Credential rotation keeps the binding.
3. **Select before admission.** Use optional `sesRecipient` in `EmailWorker` in `packages/registration/src/email-outbox.ts`. Select before locks and attempts using the canonical email. Keep operator notices, other test mail and box mail in Mailpit with no SES attempt. Apply this selection only to workers with the pilot option, preserving existing SES callers. Use the admitted attempt for the SES send. Keep refusal, suppression and settlement behavior. Queue retention and pending feedback processing go in the guide.
4. **Focused checks and rollout.** `deploy/test-cloud/ses-runtime.test.mjs` owns startup, file and pin refusal. `scripts/test-cloud-deploy.test.mjs` and `deploy/test-cloud/deployment.test.mjs` own the rendered overlay boundary. Extend `packages/registration/test/ses-smtp-settlement.test.ts` for admitted and settled mailbox mail and no attempts for capture and operator notices. Check box mail still reaches Mailpit with the switch on. After CI and landing, use the coordinated backup and image upgrade, then enable through the same-image driver. Check worker stability and send once through ordinary Cloud signup. Record provider acceptance and ask the owner for inbox receipt, SPF, DKIM, DMARC and tracking results. Document rollback and remaining feedback work in `docs/test-cloud.md` and `docs/backlog.md`. Expect 160–235 product and configuration lines and 125–175 test lines. No schema or production changes.
