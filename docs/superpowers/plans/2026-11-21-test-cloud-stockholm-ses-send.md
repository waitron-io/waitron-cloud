# Switch the hosted test Cloud to Stockholm mail for one mailbox

The owner said “yes to the trial” on 19 November at 19:20 (campaign desk record `20261119-1848-K-amazon-email-trial.md`). On 21 November at 14:02 the watcher directed Lane K to switch the existing hosted test Cloud and send its first real email to the owner's verified mailbox. This replaces the isolated-run proposal and follows the [19 November plan](2026-11-19-test-cloud-amazon-ses.md). The only live recipient in this slice is that mailbox.

1. **Enable through ordinary startup.** Add `deploy/test-cloud/compose.amazon-ses.yaml` after the Amazon overlay. Set `CLOUD_TEST_AMAZON_SES=1` and mount one bounded, private mode-0600 settings file read-only into the existing email worker. `deploy/test-cloud/ses-runtime.mjs` opens a regular file without following symlinks, refuses malformed settings or the wrong test origin, and returns configuration for `deploy/test-cloud/email-worker.mjs`. Basic startup uses Mailpit. A selected, invalid SES configuration stops the worker with a fixed diagnostic. No secrets in Compose environment or logs.
2. **Keep authority separate from configuration.** The watcher checks the exact sandbox scope and records a fingerprint before the build. Pin it in the test helper, covering the approved mailbox, sender, provider account, region, test origin, configuration set, two queues, topic and policy revision. Hash canonical settings excluding secrets. Require the pin before building the narrowly scoped test policy for `validateSesFeedbackConfig`. Use existing retained keys and `createSmtpAccountMailer` with exact TLS settings. Before issuing its key, restrict the existing SMTP user's grant to the owner mailbox in addition to its current sender, configuration set and owner-set boundary. Record that readback and keep credentials private.
3. **Choose before recording a send.** Add optional `sesRecipient` to `EmailWorker` in `packages/registration/src/email-outbox.ts`. Resolve the eligible configuration once per decrypted message before the SES lock and admission. Existing SES callers without this option keep their current behavior. The test worker uses SES only with an admitted attempt, and sends other test mail to Mailpit. It never falls back to Mailpit after an SES failure. Preserve existing attempt receipts, suppression, claim checks and test box mail. Production startup and broader simulator and live feedback qualification stay outside this first send.
4. **Focused checks and rollout.** File and pin checks belong in `deploy/test-cloud/ses-runtime.test.mjs`. Extend `packages/registration/test/ses-smtp-settlement.test.ts` to prove one admitted/settled owner send and zero SES attempts for a second address captured with Mailpit behavior. Check the Compose override selects only this worker, then deploy the reviewed image through the existing test Cloud rollout and exercise the ordinary signup email once. Confirm the bound provider receipt and ask the owner for inbox receipt and SPF, DKIM and DMARC results. Leave the opt-in available, and document disabling it in `docs/test-cloud.md` plus remaining D102 work in `docs/backlog.md`. Estimate 115–175 product/configuration and 75–115 test lines. No new schema or AWS resources.
