# Stream whole-year Cloud backups

A venue can send, retain, verify and recover a whole-year backup through the local test Cloud with bounded memory. The owner's 17 November 23:16 decision chose whole-file streaming. Lanes G and J agreed the trial bounds at 23:29–23:30. Build follows Claude review and watcher clearance.

## Transfer and retain

Accept up to **2 GiB ciphertext (2,147,483,648 bytes)**, twice Lane M's 1,001,932,236-byte gzip and 28% above Lane E's 1.68 GB sample. J owns gzip inside WBK1, raw WBA1 compatibility and the 4 GiB expanded WBA1 check. M6's compact database is 3.31 GB. Linear growth puts the expanded limit at roughly 15–16 months. An over-limit capture refuses before replacing a previous copy. The present 14-minute object transfers stop five seconds before grant expiry and need about 9.55 Mbit/s for M6 or 20.46 at the cap, before overhead.

Use one ciphertext cap for staged storage, catalogue, verification request/result and bound child input. Use the existing exact length and SHA-256 stage before conditional retention. Set private, quota-bounded **disk** stage roots for account in `deploy/test-cloud/compose.yaml` and the local backup worker in `compose.yaml`. The current `/tmp` is RAM. Keep legacy and buffered paths at their existing ceilings. Keep historical capacity receipts readable.

Recovery keeps the existing scoped read grant, exact verified-point binding and live owner check. Run large publication only through the venue-level path, which releases authority locks during object I/O. In `captures.ts`, `catalogue.ts`, `storage.ts` and test `proxy.cfg`, trial 50 seconds for the signed publish route and give authentication, lock waits, staging, conflict comparison and retries one shared Cloud cut-off of 45 seconds or signed issuance plus 55 seconds, whichever comes first. Keep the final live authority and exact 60-second signature check.

## Verify and qualify

Keep existing one-child isolation and 1 GiB memory. The operator supplies one dedicated, quota-bounded 16 GiB encrypted Docker volume for the existing worker slot, with no per-attempt host provisioning. Mount it also on the trusted local worker so its controller can check volume identity, capacity and emptiness. The isolated child mounts only that volume at `/scratch`, with no network, socket or writable root. Under the existing journal, remove the exact child, clear the owned volume contents and confirm emptiness before releasing the slot, including after cancellation or restart. Uncertain cleanup prevents admission. Use the existing opt-in local integration worker and update the containment design and guides.

Update `worker.ts`, `verification-admission.ts`, the bound launcher, watchdog, child and controller together. Use a six-minute verification lease and five-minute deadline bound to the existing attempt in the large profile. Stop the worker's stage download, launcher, supervisor and child by the attempt deadline minus 30 seconds. Supply the cut-off at container creation. Cleanup or admission after that attempt deadline cannot qualify the result. Pin J's matching runtime. Leave the legacy verifier path alone.

Start with failing tests. `object-transfer`, `storage` and `verification-protocol` own cap, exact bytes and retry. PostgreSQL `venue-service-storage`, `verification-admission` and `worker-admission` own live authority, replay and expiry. The bound-container and controller tests own containment, full disk and owned cleanup. Reuse the existing test Cloud and TLS storage fixtures. First require near-cap signed publication and retry. Then run a genuine M6-sized capture through retained verification, owner approval and streamed recovery. Measure byte count, digest, time, peak memory, peak disk and cleanup. If either run misses the bounds, keep 512 MiB and return to the watcher with the failed stage and measurements. Estimate 450–550 code and 350–450 test lines.
