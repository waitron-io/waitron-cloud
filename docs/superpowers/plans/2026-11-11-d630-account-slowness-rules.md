## Existing code and decisions (source assessment, not execution evidence)

Reuse `deploy/local-stack/account-failure-rules.mjs` and its existing tests: explicit configuration, cumulative differences, window history, resets and rounding. `packages/account-http/src/request-metrics.ts:21–27` records measured `count` separately from `total`, with cumulative buckets at 0.05, 0.1, 0.5, 1 and 5 seconds. Parser failures are untimed (`packages/account-http/src/server.ts:81`). Collector acquisition/formatting already validates snapshots; do not add validation behind that boundary.

- Extend existing `CLOUD_ACCOUNT_FAILURE_RULES` JSON with optional `slownessTargets`; keep `failureTargets` required and unchanged. All existing configurations remain valid. Slowness shares the explicit existing `fast`/`slow` windows and multipliers; no second setting, Compose edit, diagnostic, on/off switch or separate windows. Absence of `slownessTargets` disables only slowness; if present it must be nonempty. Every value remains required with no defaults.
- Each slowness target has exactly `{limitSeconds,allowance}`. Allow six timed groups: `health`, `account`, `installations`, `relay`, `portal`, `other`; reject `parser`. Limit must match one of `[.05,.1,.5,1,5]` seconds, copied locally as existing groups already are; `RequestMetrics`-based boundary tests catch drift. Allowance is finite in `(0,1]`. Keep existing required window/multiplier validation and `invalid_account_failure_rules` diagnostic; reject missing/unknown keys and invalid values, without new product/order restrictions.
- Preserve `parseFailureRules`/`createFailureRules` signatures, errors and failure-row shape. Extract one private share evaluator with thin failure/slowness wrappers in the same `.mjs`; `createSlownessRules(config,options)` reads the optional targets and shared windows. No second engine or new public configuration API.
- Project each group/outcome into cumulative denominator/within-limit counters. Failure: denominator=`total`; within=`total` for success/refused, otherwise0. Slowness: denominator=`count`; within=the selected bucket. For a window, bad=denominator increase minus within increase, summed over outcomes. Exactly-at-limit is allowed; untimed requests never dilute measured share. Reuse threshold comparison `share ≥ allowance × multiplier × (1 − 1e-9)` and all baseline/slack/pruning/reset/unknown logic. Include decreases of measured/selected-bucket counters in the shared reset detection; preserve current failure counter resets.
- Collector creates the optional slowness wrapper from its existing `failureRules` configuration and updates both from the same reading/time. Reuse acquisition availability, freshness and one metric-rendering loop. Export `waitron_cloud_account_slowness_rule_ready{group,rule}` and `waitron_cloud_account_slowness_rule_breached{group,rule}`, contiguous gauge families with bounded labels and `fast|slow`. Unknown means ready0 and omitted breach. Existing failure metrics, `/status`, raw suppression and polling stay unchanged.
