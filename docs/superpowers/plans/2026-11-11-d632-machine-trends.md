**Explicit settings and calculation.** Add optional `CLOUD_MACHINE_TREND_RULES` JSON with exactly `machine`, `windowMs`, `horizonMs`, `limits:{disk,memory,load,email,backup_due}`; unset/empty disables. Require all fields, no defaults; reject unknown keys before collection. Alias is `[a-z0-9_-]{1,32}`, safe integer window ≥ collection interval, safe integer horizon > 0; limits are finite positive numbers (disk/memory ≤ 1). Disk is `1-bavail/blocks`; memory is `1-MemAvailable/MemTotal`; load is 15-minute load/logical CPUs; queue limits are seconds. One window/horizon serves all five signals; it is a deliberate first-version limit, not a learned baseline.

Email uses oldest pending/processing creation time and pending+processing counts; `backup_due` uses oldest overdue availability/expired lease and `due` count, not enqueue age or healthy running-job age. Zero relevant work is age zero. With relevant work, absent/invalid/future timestamps are missing. Derive ages at snapshot `checkedAt`, reject stale/future snapshots and keep their observation time; failed operations inspection makes queues unknown, without hiding machine or account rules. Queues are stack-wide, not worker-owned. A stuck queue item ages one second per second, so its warning is an earlier age threshold, not a prediction of arrivals.

Extend `account-failure-rules.mjs` with `parseTrendRules`/`createTrendRules`. Extract only its private bounded retention/baseline helper for reuse: existing share rules keep their counter-reset predicate; trends keep history per signal and reset only for backward time. Collector/machine restart loses in-memory history already; add no boot-ID or capacity tracking. Select the latest baseline at least one window old within the existing interval + timeout + 2-second allowance. Rate = `(current-baseline)/elapsedSeconds`; breach = current ≥ limit, or positive rate reaching limit within `horizonMs/1000`. A current-limit breach needs no baseline; otherwise incomplete coverage is unknown. Falling readings clear normally. Each signal has independent acquisition/freshness; missing or expired readings give ready0 and no breach. Export contiguous gauge families `waitron_cloud_machine_trend_rule_ready{machine,signal}` and `_breached{machine,signal}` (0/1 only when ready), with the five fixed signal labels.
