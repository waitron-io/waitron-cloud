# Coordinated CI reader audits implementation plan

> **For agentic workers:** Use `superpowers:executing-plans` for the already authorised native inline implementation, task by task after this docs milestone lands. Do not start implementation in the design firing or request another approval cycle.

**Goal:** Renew four existing CI reader audits together without changing their content exemptions or conservative behavior.
**Architecture:** One strict shared policy replaces three mutually fingerprinted certificates; each mode retains its own complete other-input inventory. Keep existing planner, checker, summary and receipt interfaces.
**Tech stack:** Node 26, pnpm 9.15.0, Git objects and built-in Node tests; no new dependency.
**Spec:** [Coordinated CI reader audits](../specs/2026-10-16-coordinated-ci-audits.md). Read it alongside this plan and the earlier precise-selection documents.

## Constraints and review focus

Preserve every behavior listed in the spec: old/head audit checks, valid base, mode/type/missing-test refusals, exact changed paths/checkout, ownership/privacy/security assertions, manifest projection/dependency validation, workspace completeness, five lock receipts, mixed/unknown full fallback and equal-tree merge reuse. No runtime/provider/migration/fiscal/deadline/trigger/schedule/grouping/cost-target change. Never auto-renew on CI or silently refresh saved dependency/execution fixtures. Comments explain invariants and why; all commits use `git commit -s`, and hooks stay enabled.

Five review risks have explicit controls below: peer-field corruption (task 1), bad base masked by good head (task 2), real file-mode/submodule changes (task 2), fixture assertions bypassed during migration (task 3), and staged versus committed tree drift (task 4). All new code/tests wait until you read the TDD skill. For each behavioral change, write the test, run it and retain its expected assertion failure before implementation; rerun it green afterward. Import errors alone do not count when an existing public entry can demonstrate the missing behavior.

`fingerprintInputMode` preserves raw ordered NUL records and the exact exemption table. Validate required regular inputs before excluding them. Lock projection validation/hash uses the existing algorithm. `readInputAudit` validates the whole schema and policy mode, including duplicate JSON members; it does not demand unrelated modes' content checks. `auditInputMode` compares only its mode plus lock projections when applicable. The generator/checker uses all four modes. Keep immutable revision validation in selectors; only explicit generation accepts a Git tree object.
