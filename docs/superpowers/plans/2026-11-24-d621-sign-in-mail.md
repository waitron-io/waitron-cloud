# D621 sign-in mail in the machine-loss rehearsal

When a password request finishes on the server but the observer loses the reply, its email can arrive after a second request. The machine-loss observer should wait for the email for the challenge it received and count recovery only after the existing confirmation endpoint returns HTTP 200.

- In `scripts/test-cloud-integration.mjs`, keep the password reply's `expiresAt` with the pending challenge. The English test email prints that same date and time to the second in UTC. Compare the expiry line after normalising whitespace, skip older mail and keep the challenge through an inbox timeout. Keep the 60-second replacement for a stranded delivery. The confirmation endpoint still decides whether the code is valid. Two challenges issued in the same second can have the same printed expiry. If confirmation refuses a code, the probe fails and a new sign-in can start on the normal schedule.
