# Register a new box from Waitron

Sign in or sign up from the box after creating its administrator. Pairing runs without typing a code, picking a business or confirming twice. The completed journey offers address lookup before the venue form is saved and Cloud email at the email step. Skip keeps manual addresses and your own email server. Connect later from the box with its saved venue details. The owner set this direction on 20 November at 13:11, 13:20, 13:49 and 13:54 in Lane K's questions. Lane D owns Waitron and the shared signing contract. This supersedes the [link-only plan](2026-11-19-cloud-one-click-pairing.md).

## 1. Connect an installed test box

- In `packages/account-http/src/pairing.ts` and `packages/registration/src/pairing.ts`, extend signed `/api/pairing/{start,status,complete}` and account `/api/account/pairing/approve`. Require the new shared contract version, `test-venue-levels`, a signed `test` environment and the configured test box key. Use the existing key, protected code, throttles and fresh enrolled account proof. Tie that proof to the same request and the administrator's deliberate Connect action on the trusted box. A forwarded link or an existing Cloud session alone grants nothing. The watcher must settle the sign-in surface and that handoff before build.
- Add a migration for the new account-bound pairing state and the venue's trading address. The new version exposes `account_bound`. Keep old state replies, pending session checks and expiry. If unfinished authority expires, return to sign-in or Skip without losing the local form. Recover completed IDs via signed status after a lost reply.
- Complete signs `countryCode`, `venueName`, `tradingAddress`, `taxNumber` and the existing form's `legalName`. Under the account lock, lock eligible organisations and businesses in the existing order, serializing creation in a shared organisation. Match the configured country and trimmed, case-insensitive tax number only among owned, registration-enabled businesses. Reuse a unique match. With none, create the business in the sole eligible organisation, or create a new account's first organisation and business using the legal name. Blank existing numbers never match. If ambiguous, report that Cloud could not file the venue so local work can continue and the owner can correct business details.
- Reuse `RegistrationStore` to create a new venue on every fresh box with no Cloud venue ID. Preserve matched business details. Add the migration to `migrate.ts`. In both packages' `test/pairing.test.ts`, prove old routes, forwarded-link refusal, key and account binding, tax match within scope, new venue per box, ambiguous refusal and concurrent or lost replies. Estimate +180–270 implementation lines, +130–200 tests.
