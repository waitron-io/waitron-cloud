## 1. Connect an installed test box

Every box call is a POST to `/api/pairing/{start,redeem,status,complete}` with the existing `{payload,signature}` envelope. Sign the exact UTF-8 JSON array `["waitron-cloud-pair-v4",cloudOrigin,action,requestId,publicKey,"test",issuedAt,args]`. Reuse the Ed25519 SPKI key, unpadded base64url, UUID checks, exact re-encoding and 60-second timestamp rule. This version creates only new venues.

| Action | Signed args in order | Successful response |
| --- | --- | --- |
| Start | `[redirectUri,state,codeChallenge]` | `{requestId,state:"awaiting_cloud",expiresAt,authorizationUrl}` |
| Redeem | `[code,codeVerifier]` | `{requestId,state:"account_bound",expiresAt}` |
| Status | `[]` | `{requestId,state,expiresAt}`, state is `awaiting_cloud`, `account_bound` or `complete`, with `registration` only when complete |
| Complete | `[countryCode,venueName,[addressLine1,addressLine2,postalCode,city,province],taxNumber,legalName]` | `{requestId,state:"complete",expiresAt,registration}` with the existing registration shape |

The box generates state and verifier from separate 32-byte random values. Derive the challenge with [PKCE S256](https://www.rfc-editor.org/rfc/rfc7636.html#section-4.2). Bind the attempt to the initiating tab, its local session and box key. An identical start returns the original expiry and Cloud URL `/login?request_id=…&state=…&code_challenge=…&code_challenge_method=S256`. Match these values against the signed start. Keep the attempt in Cloud tab storage and clear it on sign-out, expiry or leaving the flow. When fresh Cloud sign-in finishes, record its session and proof on the pending request. Authorize requires that same session and a valid passkey, app or recovery proof made since the request started. Then the portal makes a same-origin, CSRF-checked `POST /api/account/pairing/authorize` with `{requestId,state,codeChallenge}`. Its `{returnUrl}` uses the bound `/cloud/pairing/callback` with `request_id`, `state` and `code`. For cancel or expiry, same-origin `POST /api/account/pairing/cancel` checks `{requestId,state}` without a session and returns the bound URL with `error=access_denied|expired` in place of the code. Keep callback parameters out of history, logs and referrers.

Before signing redeem, check the initiating tab's state and the original fresh local administrator session on a same-origin box POST. Cloud checks the key, 60-second code and verifier and consumes the code when it binds the account. Store the code hash with the account, session and security revision. Authorize retry replaces the unused code for that same account and session. Redeem within 10 minutes of start. Redeem updates `expiresAt` to that session's absolute expiry. Status and complete report that deadline. Expired unfinished requests and wrong, expired or spent redeem codes return 400 `pairing_unavailable` under the existing IP and key throttles. Signed status recovers a lost reply, even after expiry for an unrevoked completed installation. Complete rechecks account authority before filing. An expired or cancelled attempt keeps local forms and offers sign-in again or Skip.
