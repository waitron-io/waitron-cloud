## Decisions

- **Required configuration:** optional `CLOUD_ACCOUNT_FAILURE_RULES`, a JSON object containing exactly `successTargets` (all seven fixed groups: `health`, `account`, `installations`, `relay`, `portal`, `other`, `parser`) and `fast`/`slow` (each exactly `windowMs`, `multiplier`). Every value is mandatory when enabled; no trial defaults. Unset/empty disables only these rules. Targets are finite fractions strictly between 0 and 1; multipliers finite and positive, with `(1-target)×multiplier ≤1` for each group. Windows are safe integer milliseconds, `intervalMs ≤ fast.windowMs ≤ slow.windowMs ≤ 4094×intervalMs`; this last limit bounds storage, not trial policy. Reject unknown/missing keys, malformed JSON and invalid values before listening or collecting, with a fixed diagnostic naming the setting and never its contents. `compose.yaml` passes this variable only to `operations-collector`, using empty solely to mean disabled.
- **Calculation:** for each group/window, bad share = counter differences in `server_error + timed_out` / differences across all four outcomes; refused requests contribute only to the denominator. Compare share **≥** `(1-successTarget[group])×rule.multiplier`. This is a request-weighted rolling share, not requests per second or a condition required at every poll. Timing histograms/slowness rules are outside this slice.
- **Coverage and clearing:** timestamp successful readings at acquisition with the existing injected clock. Use the latest sample at or before `now-windowMs` and the newest sample; disclose that the measured span can exceed the configured window by one freshness allowance. Require continuous readings with gaps no greater than existing `intervalMs+timeoutMs`. Startup/incomplete coverage or zero requests means unknown, never healthy. Recompute each poll; a covered nonempty window below threshold clears immediately, without latching or recovery counters. Missing series mean zero. Restart identity change, any counter decrease, failed acquisition/operations collection, expired freshness, or non-increasing time discards history; the next valid reading is a new baseline. Check elapsed freshness before accepting a recovery poll even if nobody scraped during the gap.
- **Bounded state/output:** retain only timestamp, process identity and 28 totals per reading, the slow window plus its one preceding sample, hard maximum 4096 readings (evict oldest; lost coverage means unknown). No durable store, extra process or timer. New `deploy/local-stack/account-failure-rules.mjs` exports `parseFailureRules(raw, intervalMs)` → validated config or null, and `createFailureRules(config,{intervalMs,timeoutMs})` → `update(validatedSnapshot,nowMs)`, `reset()`. Update returns 14 `{group,rule,ready,breached}` rows, with `breached:null` when unknown. Collector accepts optional `failureRules` through `createCollection`/`serveCollection`; exports `waitron_cloud_account_failure_rule_ready{group,rule}` as 0/1 and `waitron_cloud_account_failure_rule_breached{group,rule}` only when ready. Disabled emits neither family; failed/stale enabled collection emits readiness 0 and no breach values. Preserve existing counts, freshness, `/status` and operations diagnostics. Labels use only the seven groups and `fast|slow`.
