# Disposable test server implementation plan (D592)

**Goal:** Deliver isolated local slots within days of the server arriving, then move selected Cloud CI work onto the same disposable-machine system. Waitron follows a separate inventory.
**Design:** [One Mac controller and one fresh VM per turn/job](../specs/2026-11-06-disposable-test-server-design.md). The server keeps its pinned SSH host key and restarts unattended; long-lived GitHub, package and provider credentials stay on the Mac.
**Status:** approved on 6 November 2026; the owner authorized slice 1 on the supplied bridge. The [manual slice](https://github.com/waitron-io/waitron-cloud/pull/1031) is available. The server startup implementation is in `deploy/disposable-tests/startup.py`; run `node --test scripts/disposable-tests/session.test.mjs` for its portable checks. The Mac entry point is `deploy/disposable-tests/mac-controller.py`, with a launchd template; interrupted-turn reconciliation is in `scripts/disposable-tests/manual.mjs`. Coupled permanent publication and runtime qualification, an actual coordinated reboot, frozen transitive packages, measured capacity and later CI activation remain open.

The estimates below start when the server address and access arrive, and assume working KVM, usable disk and unchanged dependency interfaces. They are planning estimates, not measured delivery promises. Each slice has a useful result of its own. Before implementation, read the TDD skill, observe a failing behavioral test for the named assertions, implement minimally and watch it pass; sign off every commit and retain active hooks.

## 1. One isolated local slot: first 1–2 days

**Proposed files:** `scripts/disposable-tests/{leases,host,local}.mjs` with owning tests; `deploy/disposable-tests/` for pinned guest recipe/systemd service; a local helper beside the existing shared test-box helper, deployed only after watcher approval.

- [ ] Implement only local ownership: `reserveLocal({lane,turn,snapshot,argv}, budget)` and generation-checked start/release. First failing tests prove two reservations cannot own a slot, an old generation cannot release its successor, duplicate requests create one VM, busy/down returns 75 within 10 seconds, and uncertain destruction never grants reuse. No GitHub event/admission types belong in this slice.
- [ ] First host/local tests refuse host sockets, bind mounts, shared writable stores, escaping snapshots and neighbor/management access. Exercise command exit 3, cancellation during copy/install/run, controller death, failed boot and disk full on a small throwaway filesystem. Cleanup touches only recorded VM/disk/network IDs, completes within 120 seconds or quarantines, and never prunes shared state.
- [ ] Implement the minimal full-VM adapter with private Docker and per-turn disk/store. Preserve the real command's assertions, timeout and status after successful cleanup; cap a turn at 55 minutes. Start server management with systemd and the Mac controller with launchd. Pin the normal SSH host fingerprint on the Mac. Reboot the server and prove automatic recovery without console enrollment or replaying interrupted candidate processes.
- [ ] Run the named owning test files explicitly with `node --test scripts/disposable-tests/leases.test.mjs scripts/disposable-tests/host.test.mjs scripts/disposable-tests/local.test.mjs`, then a real bounded PostgreSQL/Docker turn, cancellation and clean-next-guest check. Qualify temporary dependency access without copying a long-lived package token. Record exact snapshot/command/counts and cleanup. This delivers one usable local slot without any GitHub App or runner registration.

## 2. Several measured local slots: following 1–2 days

**Files:** extend the same local budget/host tests; add `scripts/disposable-tests/benchmark.mjs` and its owning test. Keep GitHub admission out of this slice.

- [ ] Begin with one 4-vCPU/16 GiB VM with 64 GiB maximum private disk. Reserve at least 4 physical host cores including sibling threads, 16 GiB host RAM and 20% usable disk. Measure actual topology, usable storage, CPU/throttling, peak memory, I/O pressure, disk high-water, network, boot/run/cleanup time and counts before selecting capacity. Sixteen physical cores are not sixteen standard runners.
- [ ] First benchmark tests reject mismatched workloads/counts/deadlines, missing samples, reused guests, overcommitted memory/disk and released quarantines. Compare at least 3 cold and 3 warm fresh-guest trials at one slot, then two and three concurrent slots, including Docker/browser work. Preserve all assertions and existing limits; require no collision/OOM/reserve breach and cleanup <=120 seconds. Follow the design's hosted comparison gates; retain the lower count on failure.
- [ ] Prove two lanes can use identical ports/container names independently, cancellation of one preserves its neighbor, and a new guest sees none of its predecessor's files. Deploy the watcher-approved helper, which prints shared mode/generation and returns75 promptly when unavailable. Existing box/Mac fallbacks remain. This slice supplies multi-lane relief before CI begins.

## 3. Cloud CI canary and outage/mode switch: next 2–3 days

**Proposed files:** `scripts/disposable-tests/{admission,registrar,control}.mjs` with owning tests; extend Mac controller/ledger; temporary non-required canary workflow. One repository-level GitHub App on the Mac, no test-box dependency.

- [ ] Add CI identity to the working local ledger: repository/workflow/head/tree/run/attempt/job, runner ID and immutable deadlines. First admission/registrar tests reject foreign identities, unapproved heads, changed control definitions, candidate-executed controller code, stale/replayed attempts and lost-response duplicate registration. Reviewed-main policy reads immutable candidate data only. One JIT runner accepts at most one job; destroy its full VM afterwards.
- [ ] Keep the App key, long-lived package/provider credentials and durable state on the Mac. Use that one App for JIT Administration/write, cancellation Actions/write and routing Variables/write. Confirm owner setting for ALL external contributors before external work. Rehearse broad matching-label competition with synthetic inputs; labels do not authorize jobs and JIT cannot bind a runner to an exact job ID. Retain the public-repository residual risk for owner review.
- [ ] First controller tests cover server absent before any runner, missed events, 15-minute queue expiry, server death before pickup/during work, API failure, controller restart, stale cancellation and a manual rerun racing run-ID cancellation. Preserve job/child deadlines. While Mac/GitHub are available, enforce the design's 15-second polling, 60-second health-loss and 120-second terminal-readback bounds. When the Mac is down, queued jobs may wait up to GitHub's 24 hours; reconcile current state automatically when it returns. No standby or mirrored ledger.
- [ ] Implement the design's exact watcher/lane commands: `control.mjs mode hosted --reason server-unreachable`, `status`, `recover --mode hosted`, and `mode server --reason qualified-recovery`. First tests prove local admission stops before a GitHub variable update, disagreement keeps it closed, shared mode generation changes atomically, and helpers display it. Prove the hosted switch, cancellation, same-candidate fresh hosted attempt and actual runner readback with the server unreachable. Missing/invalid routing variable defaults hosted. No owner-only overnight step.
- [ ] Run explicit new owning tests plus affected native evidence guards. In a canary prove one-job VM destruction, reboot recovery, transient credential cleanup, Mac-down reconciliation and actual driver refusal of cancelled/missing/unfinished required work under the shared landing lock. Cloud has no GitHub branch protection. Do not activate CI until those behaviors, fresh-attempt mode evaluation and residual-risk review qualify.
