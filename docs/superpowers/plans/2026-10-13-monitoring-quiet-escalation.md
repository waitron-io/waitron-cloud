# Monitoring quiet periods and one reminder implementation plan

> **For agentic workers:** Use `superpowers:executing-plans` inline. Owner unattended workflow overrides interactive approval, per-task agents and per-task reviews. Read the TDD skill before writing any test or implementation. This handoff writes docs only; the Lane D driver reviews and lands these docs before one cohesive implementation PR.

**Goal:** Let a brief incident recover silently and optionally remind only its original, already-notified eligible owners once.

**Architecture:** Keep the immediate incident projection and existing revision checks. Add durable per-opening episodes and recipient slots; reconcile notifications in the existing venue transaction, and deliver through the existing encrypted claim-bound email queue.

**Tech stack:** Node >=26, TypeScript, pnpm 9.15.0, PostgreSQL 18 fixtures, node:test, local Mailpit.

**Spec:** [2026-10-13-monitoring-quiet-escalation-design.md](../specs/2026-10-13-monitoring-quiet-escalation-design.md). Its consumer map and every invariant apply to all five tasks.

## Global constraints

- Base `d681db284ac8babeffb9f1029c2c32f8dc47701c`; current count/tail 36/`036_relay_operator_stop.sql`; append 037 only. Recheck manifest on rebasing, never edit landed SQL.
- `quietSeconds`/`reminderSeconds` and their `CLOUD_MONITOR_*_SECONDS` settings default to 0; accept finite integer 0..604800 only. Capture per episode. One reminder per episode/account, anchored to committed opening `sent.finished_at`; quiet anchored to database opening.
- Recipient snapshot at opening; current permissions/preference/address at enqueue and handoff. No recovery or reminder without this episode's sent opening. No production thresholds, live providers/mail/deployment, fiscal work or unrelated queue changes.
- Preserve nine issue kinds, incident status/revision, portal/API shapes, legacy ciphertext and all old behavioral/security assertions. Notification groups and schedule admission are at most 100 per statement, transactional; network is outside locks.
- Every feature/fix starts with an observed failure for the intended reason, then minimal implementation and the same passing check. Commit passing coherent work with `git commit -s`; do not bypass hooks. Keep changed-check inventory for the PR and Lane D's required FYI.

## Review focus

1. Receipt arrives after recovery: eventually one authorized recovery, without allowing an unsent opening (Task 4).
2. Reused incident row and unchanged status: no cross-episode mail or duplicate reminder (Tasks 2/3).
3. Enabling/adding an owner during quiet time: no historical notice, even if later eligible (Task 2).
4. Cleanup or lease takeover races: keep needed receipts; stale claims never authorize mail/receipts (Tasks 3/4).
5. Old backups and current-config changes: no retroactive mail and no deadline reset (Tasks 1/5).
