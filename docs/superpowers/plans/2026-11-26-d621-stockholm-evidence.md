## PR 2 · Record failures and finish the sequence

- In `scripts/p1-observer.mjs`, always gather evidence during measured Stockholm stops. Record baseline failures before calling `ready()`, and record probe errors, missed recovery deadlines and failed reconciliation during the stop. At the end of the hold, cancel and record outstanding checks, including the last backup read, then return a failed observation before the stop signal expires. Keep fail-fast behaviour for free local rehearsals and worker-loss proofs.
- In `scripts/kubernetes-services.mjs` and `scripts/test-cloud-integration.mjs`, retain failed session, publication, signup, inbox and backup checks across the three stops. Return these as results from `whileStopped` so the launcher restarts the machine, then require verified rejoin. On the full restart, record failed before/after service checks and outage probes the same way. Attempt retained backup inspection and an isolated restore of a new capture when each check’s prerequisites allow. Keep the fault and rejoin confirmations, cancellation, hard deadlines and restore safeguards. List any checks those gates prevent. Defer the separate staff-notice, inbox and Billing trials.
- Before each stop and through rejoin, sample `pg_postmaster_start_time()` each second under the launcher’s stop signal. Expose `kubeOn` bound to the selected controller and reselect after connection loss. Bound each read. Record the writer’s node, pod name and UID, restart count, last exit reason and gaps. At the end of the hold and after rejoin capture current and previous PostgreSQL logs, operator and Flux logs, and cluster events. Keep timestamps, component, reason and SQLSTATE fields, omitting SQL and private message text. Stream this evidence to the launcher’s private stderr log outside scratch, opened by the operator with `umask 077`. Flush a failure summary before teardown even on abort. Any failed qualifying check still makes the run exit nonzero.
