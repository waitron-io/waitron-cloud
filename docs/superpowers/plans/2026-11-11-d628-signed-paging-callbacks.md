**Interface and flow:** `createPagingCallbackListener(options): RequestListener` returns a Node HTTP handler for caller-owned `createServer(...).listen(0,'127.0.0.1')`. Options supply HTTPS `origin`, Twilio `{provider:PagingProvider,authToken:string}`, Vonage `{provider:PagingProvider,apiKey:string,signatureSecret:string}`, `attempts:()=>readonly PageAttempt[]`, and synchronous `onEvent:(event:TrustedEvent)=>void`. Use Node 26 HTTP/crypto, no dependency or CLI. Caller records accepted attempts before submitting callbacks; its `onEvent` appends trusted evidence and calls `pageDecision` with its notification/attempt facts.

- Accept exactly D627's `/paging/{incidentId}/{notificationId}/{provider}/{kind}` paths. Authenticate, call that provider's `readTrustedEvent(kind,parsedFields)`, then require a matching caller-supplied incident/notification/provider and accepted resource ID: text IDs for text, call IDs for call/input. Reject unknown/failed submissions and mismatched kind/body shapes. Vonage signatures do not authenticate the URL; never derive context from JWT claims or body alone.
- Bound bodies to 64 KiB; reject malformed/nonobject JSON, duplicate form/query fields and unsupported methods/media. Compare signature bytes in constant time. Fixed errors reveal no secrets. Accepted input returns Twilio XML `<Response/>` or Vonage JSON `[]`; reports return 204. Errors: 400 malformed, 403 unauthenticated/unbound, 409 replay, 405/415 unsupported, 413 oversized.
- After authentication and binding, synchronously reserve replay keys before invoking `onEvent`: Vonage Voice account/jti plus provider/resource/kind/state/digits for normalized events. No eviction during the listener session; status progression remains valid. A second callback cannot emit again, including a newly signed duplicate. Restart loses this memory; reloading old attempts can accept old signed callbacks again. No durable replay claim or timestamp-based expiry policy.

**Provider rules, primary docs cross-checked 11 November 2026:**

- [Twilio security](https://www.twilio.com/docs/usage/security): “sort all the `POST` parameters alphabetically”. Support form POST; sign configured origin plus exact path/query, then **all** Unix-sorted decoded fields, with AuthToken HMAC-SHA1 and base64 `X-Twilio-Signature`. Never trust Host/Forwarded for origin; retain reader AccountSid checks.
- [Vonage SMS signing](https://developer.vonage.com/en/getting-started/concepts/signing-messages): “Remove the `sig` parameter before generating your signature”. Pin SHA-256 HMAC, hexadecimal `sig`, no weaker fallback; sort remaining fields including timestamp, replace value `&`/`=` with `_`, join leading `&key=value`. Support GET query and POST JSON as [documented](https://developer.vonage.com/en/dashboard/control/api-settings), adapting to reader fields; reject mixed query/body. D627 sets no SMS callback method. Signing needs support enablement.
- [Vonage webhooks](https://developer.vonage.com/en/getting-started/concepts/webhooks): “signed with your signature secret”. Support Voice POST JSON with Bearer JWT, HS256 only; verify signature, configured api_key, iss=`Vonage`, integer iat, nonempty jti and required SHA-256 `payload_hash` over exact raw bytes before parsing. Refuse unsigned, wrong-account and altered-body callbacks. Payload checking is mandatory locally although the docs call it optional; old Voice applications may need signing enabled.
