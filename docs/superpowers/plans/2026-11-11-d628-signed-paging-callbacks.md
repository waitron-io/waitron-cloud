**Interface and flow:** `createPagingCallbackListener(options): RequestListener` returns a Node HTTP handler for caller-owned `createServer(...).listen(0,'127.0.0.1')`. Options supply HTTPS `origin`, Twilio `{provider:PagingProvider,authToken:string}`, Vonage `{provider:PagingProvider,apiKey:string,signatureSecret:string}`, `attempts:()=>readonly PageAttempt[]`, and synchronous `onEvent:(event:TrustedEvent)=>void`. Use Node 26 HTTP/crypto, no dependency or CLI. Validate provider names/configuration at creation; duplicated credentials must match the adapters. Caller records accepted attempts before submitting callbacks; its synchronous `onEvent` appends evidence for `pageDecision`. This local rehearsal cannot accept early callbacks before `sendPage` returns its accepted IDs; document that limit, without adding a buffer.

- Accept exactly D627's `/paging/{incidentId}/{notificationId}/{provider}/{kind}` paths. Authenticate, call that provider's `readTrustedEvent(kind,parsedFields)`, then require a matching caller-supplied incident/notification/provider and accepted resource ID: text IDs for text, call IDs for call/input. Recognized events require accepted IDs; reject unbound recognized events. Authenticated callbacks that a reader cannot interpret emit nothing and receive the normal successful reply, including an input timeout without a call ID. Vonage signatures do not authenticate the URL; never derive context from JWT claims or body alone.
- Bound bodies to 64 KiB; reject malformed/nonobject JSON, duplicate form/query fields and unsupported methods/media. Require flat string-valued SMS fields, including signed timestamp; strictly validate signature encoding and decoded length before constant-time comparison (hex accepts either case). Fixed errors reveal no secrets. Accepted input returns Twilio XML `<Response/>` or Vonage JSON `[]`; reports return 204. Authenticated repeats and ignored callbacks receive the same successful response without `onEvent`; forged/unbound recognized events get 403, malformed requests 400, unsupported method/media 405/415, oversized bodies 413.
- After authentication and binding, synchronously reserve provider/resource/kind/state/digits for normalized events before `onEvent`; no separate JWT-ID cache. States collapsed by readers can be ignored with success. A second normalized event cannot emit again, including a newly signed duplicate. If `onEvent` throws, release its reservation and return 500. No eviction during the session. Restart loses this memory; reloading old attempts can accept old signed callbacks again. No durable replay claim or timestamp-based expiry policy.

**Provider rules, primary docs cross-checked 11 November 2026:**

- [Twilio security](https://www.twilio.com/docs/usage/security): “sort all the `POST` parameters alphabetically”. Support form POST; sign configured origin plus exact path/query, then **all** Unix-sorted decoded fields, with AuthToken HMAC-SHA1 and base64 `X-Twilio-Signature`. Never trust Host/Forwarded for origin; retain reader AccountSid checks.
- [Vonage SMS signing](https://developer.vonage.com/en/getting-started/concepts/signing-messages): “Remove the `sig` parameter before generating your signature”. Pin SHA-256 HMAC, hexadecimal `sig`, no weaker fallback; sort remaining fields including timestamp, replace value `&`/`=` with `_`, join leading `&key=value`. Support GET query and POST JSON as [documented](https://developer.vonage.com/en/dashboard/control/api-settings), using flat string fields; reject mixed query/body and form POST. Document required settings: GET or POST-JSON delivery receipts, signature method SHA-256 HMAC and support-enabled SMS signing. D627 sets no SMS callback method.
- [Vonage webhooks](https://developer.vonage.com/en/getting-started/concepts/webhooks): “signed with your signature secret”. Support Voice POST JSON with Bearer JWT, HS256 only; verify signature, configured api_key, iss=`Vonage`, integer iat, nonempty jti and required SHA-256 `payload_hash` over exact raw bytes before parsing. Refuse unsigned, wrong-account and altered-body callbacks. Payload checking is mandatory locally although the docs call it optional; old Voice applications may need signing enabled.
