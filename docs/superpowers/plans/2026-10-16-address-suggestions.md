# Proposed Address Suggestions Implementation Plan

> **For agentic workers:** Use `superpowers:executing-plans` to work inline, task by task. This proposal is awaiting owner review and queueing. It does not authorise implementation or release.

**Goal:** Offer optional Spanish address suggestions through an explicit Cloud account grant while keeping manual entry available at all times.

**Architecture:** Cloud owns account authority, transactional allowance reservations and isolated provider adapters. Waitron separately owns the editable draft, country-pack/server validation and whole-address confirmation. Five sequential tasks can land independently with provider dispatch disabled by default.

**Tech stack:** Existing Node 26, TypeScript, PostgreSQL, Hono, Lit, pnpm and Node test runner. Use local fakes for every provider request during development.

**Spec:** [Proposed address suggestions](../specs/2026-10-16-address-suggestions.md). Read it before executing any task; every limit and release gate below refers to that contract.

## Global constraints

This plan changes Cloud only. No fiscal allocations, hash chains, golden records or issued invoices change. Preserve behavioural assertions and existing auth, pairing and installation guards. Production lookup remains disabled; no key reads, provider calls, account changes, spending or deployment are part of these implementation tasks. Manual entry remains independent of login and quota.

The customer allowance is ten confirmations/account/UTC month, with pending reservations enforced; autocomplete abuse limits are 100/account/month and 20/day across providers. Google TOTAL ceilings are 500 validations/month, 50/day, 4,000 autocomplete/month and 400/day; each workflow permits eight autocomplete and one validation. Geoapify TOTAL ceilings are 10,000/month and 1,000/day with one automatic fallback. Shared dispatch rate is two requests/second and paid budget is USD 0. Unknown shared usage, counter freshness or billing boundary disables dispatch.

Each task uses failing behavioural tests first: run the stated command, observe the intended missing behaviour fail, implement the minimum, rerun and read the passing test count. Do not accept import errors or broken fixtures as the intended failure. Before writing any implementation or test code, read the TDD skill. Preserve original assertions when extending fixtures.

Create Cloud portal `src/address-lookup-{types,controller,screen}.ts` and matching tests; integrate through `src/{app,links,screens,locale}.ts` and the HTTP portal document allowlist.

The shared proposed interfaces use UUID strings and ISO date strings. `LookupTarget` is either a setup binding `{publicKey,localVenueId,environment,organisationId,legalBusinessId,workflowId}` or a paired binding `{installationId,workflowId}`. `LookupGrant` adds `{id,accountId,expiresAt,revision}`. `LookupBalance` is `{used,pending,remaining,resetAt}`. `LookupOperation` adds `{operationId,grantId,state,expiresAt,balance}`, with states `pending|confirmed|cancelled|failed|expired`. Require `operationId === workflowId` and at most one operation per grant.

`ProviderAttempt` is `{attemptId,operationId,provider,kind,sequence,state}` with kinds `autocomplete|validation` and states `reserved|dispatched|settled`. `LookupDraft` is a transient object with the six address fields from the spec, provider label, attribution and confirmation nonce. `LookupResult` is a transient suggestions/draft response or `{kind:'manual',reason,balance}`. These types are not storage payloads.

## Review focus

Account changes during a lock wait must remove spending authority (Task 1). Empty first-period rows, simultaneous venues and lost confirmation replies must not exceed or double-debit the allowance (Task 2). Restarts, provider-month boundaries and untracked projects must not create free capacity (Task 3). Replayed setup proofs or an installation without the explicit grant must never spend a balance (Task 4). Login changes, late responses and approval cancellation must not expose or apply an obsolete workflow (Task 5 and the Waitron handoff).
