# Custom domains on the Amazon test Cloud

A test venue on the existing Amazon machine can use an owner-controlled domain with the portal's single CNAME, get a trusted certificate and open from a phone on mobile data. The Lane K queue records the owner's 18 November 10:16 decision, “Queue it after PR 8 (Recommended)”. PR 8 (#1302) and the notice (#1303) are on main.

1. **Reuse the single-cell worker and gateway.** In `deploy/test-cloud/{remote-runtime,runtime}.mjs`, pass private check and status paths to the Amazon worker from its launcher. Wire the cell's `hasChallengeFolder`, `writeChallenge`, `deleteChallenge` and `gatewayStatus.read` to the existing challenge files and `answerableNames`. The [one-record reconciler](2026-11-17-custom-domain-one-record.md) verifies the CNAME, waits until the gateway can answer, and owns cleanup. Use its custom TLS-ALPN callbacks, which let the certificate authority check possession of the domain over port 443, in the test issuer's existing ACME client. Keep exact CSR validation and the persistent, no-contact ACME account. Assigned names still use the [existing HTTP check](2026-11-17-test-cloud-public-remote.md) and LAN uses its private issuer.
2. **Connect and test the real ingress.** In `deploy/test-cloud/compose.amazon.yaml`, give `gateway-manifest` write access to the private check volume and `gateway` read access via `GATEWAY_CHALLENGES`. The gateway writes `GATEWAY_STATUS_DIR` to a separate status-only volume that the worker reads. Extend `scripts/test-cloud-deploy.mjs` to validate these mounts and refuse access from other roles, including the internet-facing HTTP challenge service. The existing Amazon proxy forwards the custom TLS connection to the gateway and continues to terminate account HTTPS. Keep the host ports, service count and memory limits.
3. **Validate then qualify.** Observe the named tests fail before implementation and pass after it. Update `docs/test-cloud.md` and the custom-domain section in `docs/backlog.md` with the observed local result and pending live trial. After exact-head CI and merge, use the existing coordinated image upgrade on the authorised test machine. Coordinate the one record, paired test venue and phone with the watcher. Rehearse with the staging certificate authority, then record a trusted certificate and an actual page load on mobile data. Keep the machine, account and gateway identities. This slice uses the existing services and ports and requires no new spend, provider resources, schema, portal, production or Waitron changes.
