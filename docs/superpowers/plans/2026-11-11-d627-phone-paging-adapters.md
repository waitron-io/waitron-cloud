## Smallest interface and flow

- `Notification` carries incident/notification UUIDs, `locale:'en'|'es'`, fixed `service`, safe nonnegative venue count, strict UTC `since` and `fixProposed:boolean`; reject extra/free-text fields. Configuration supplies synthetic recipient/senders, credentials and fixed HTTPS origins. Incident link is `/incidents/{incidentId}`; callback paths include `/paging/{incidentId}/{notificationId}/{provider}/{kind}`. No query, token or fragment. These paths name future caller integration; no route or go-ahead page exists in this PR.
- `PagingProvider` exposes `text(notification):Promise<Submission>`, `call(notification):Promise<Submission>`, `readTrustedEvent(kind,body):ProviderEvent|null`. Submission is accepted with resource IDs, failed, or unknown. One small `sendPage(provider,notification)` awaits text submission, then ALWAYS attempts the call, including when text refuses or is unknown; returns plain submission facts. It performs no retry or callback wait.
- `pageDecision(facts):{backupNeeded:boolean;acknowledged:boolean}` is pure. Facts contain this notification’s Twilio/Vonage submissions and normalized trusted delivery/input evidence, including caller-declared unconfirmed delivery. Backup is needed after Twilio refusal/failed/unknown delivery only while no Vonage attempt exists and no matching acknowledgement exists. The caller starts the backup explicitly; there is no async handle, event bus, serialisation or persistence/rebuild layer.
- Match incident/notification/provider/resource IDs; Twilio also matches AccountSid and Vonage SMS matches api-key. Any placed matching call’s digit exactly `1` acknowledges, including Twilio after Vonage starts. Answer, completion and text delivery never acknowledge. Duplicate/unrelated events cannot request another backup. Keep text/call delivery evidence separate. For Vonage multipart SMS, accept only if every returned part succeeds, and require every returned ID’s delivered event; partial evidence stays unconfirmed.
- Local event readers consume parsed Twilio form fields or Vonage JSON. A future trusted receiver must verify provider signatures and bind callback context before calling them; no public HTTP endpoint or authentication claim here. Tests return empty TwiML `<Response/>`, NCCO `[]`, or empty successful status responses as appropriate. The later Task4a clock owns durable admission, receipts and deadlines, using an adapter around these transport functions; its planned PageAdapter is not implemented or replaced here.
- Require explicit injected fetch, never environment credentials or ambient global fetch. API hosts stay fixed; test support remaps only those hosts to random loopback ports. Refuse redirects; bound response to64KiB and caller-supplied request timeout at most10seconds; return fixed redacted errors. Transport/input waits are not the excluded incident clock.

## Wire decisions, checked against primary docs11November2026

- Twilio Basic SID/token, form POST `https://api.twilio.com/2010-04-01/Accounts/{sid}/Messages.json`: To/From/Body/StatusCallback; [message docs](https://www.twilio.com/docs/messaging/api/message-resource) say “Twilio sends a `POST` request” on status change. Read MessageSid/MessageStatus; only delivered is delivery, failed/undelivered are failure.
- Twilio call POST sibling `Calls.json`: To/From/Twiml/StatusCallback, StatusCallbackMethod=POST, repeated StatusCallbackEvent=answered/completed; [call docs](https://www.twilio.com/docs/voice/api/call-resource) say answered sends “an `in-progress` status”. Read CallSid/CallStatus; busy/failed/no-answer/canceled are failures. Inline Gather uses input=dtmf,numDigits=1,timeout=10,action=per-notification input URL,method=POST, with nested Say. [Gather](https://www.twilio.com/docs/voice/twiml/gather) says its timeout “expresses its value in seconds”; input is CallSid/Digits.
- Set explicit Say voices Google.en-GB-Standard-N/en-GB and Google.es-ES-Standard-A/es-ES, rather than the account default. Twilio’s [published voice table](https://www.twilio.com/en-us/changelog/general-availability-google-voices-for-say) lists “Google.en-GB-Standard-N” and “Google.es-ES-Standard-A”; [Say](https://www.twilio.com/docs/voice/twiml/say) says “set the `voice` attribute for a specific `<Say>` instruction”. This checks documented configuration, not audible quality or live availability.
- Vonage form POST `https://rest.nexmo.com/sms/json`: Basic API key/secret; from/to/text/type=text for fixed English wording or unicode for Spanish/status-report-req=true/callback. [SMS reference](https://developer.vonage.com/en/api/sms) explicitly says “Base64 encoded API key and secret joined by a colon”, so the review’s tentative body-only-auth claim is not taken. Check all messages[].status=0, message-count and message-id values; DLR JSON uses messageId/status/api-key. [Encoding docs](https://developer.vonage.com/en/messaging/sms/guides/concatenation-and-encoding) say parts appear in the “`message-count` property in the response body”.
- Vonage JSON POST `https://api.nexmo.com/v1/calls`: to/from phone objects,event_url/event_method=POST, inline ncco talk then input; obtain a fresh Bearer JWT through injected `token():Promise<string>` for each call. [Voice API](https://developer.vonage.com/en/api/voice) names authentication “Your JSON web token.” Talk uses en-GB/es-ES and `bargeIn:true,bargeInType:['dtmf']` so press1 during the prompt reaches the following input; the [talk reference](https://developer.vonage.com/en/voice/voice-api/ncco-reference#talk) says this lets callers choose without listening to the whole message. Input has type=['dtmf'],dtmf={maxDigits:1,timeOut:10},eventUrl=[per-notification URL],eventMethod=POST. [NCCO](https://developer.vonage.com/en/voice/voice-api/ncco-reference#input) requires eventUrl “MUST be an array”; [input callback](https://developer.vonage.com/en/voice/voice-api/webhook-reference#input) names uuid/dtmf.digits and warns uuid “might not appear when an input reaches a DTMF timeout”. Missing identity never acknowledges.

Use service keys/labels cloud=Waitron Cloud/Waitron Cloud, remote_access=Remote access/Acceso remoto, backups=Backups/Copias de seguridad, email=Email/Correo electrónico, hosted_servers=Cloud-hosted venue servers/Servidores de locales alojados en Cloud.

ES text: “Alerta de Waitron Cloud: {service}. Locales afectados: {count}. Desde: {since}. {fix} Detalles: {link}” Voice: “Alerta de Waitron Cloud: {service}. Locales afectados: {count}. Detalles enviados por SMS. Pulsa 1 para confirmar la recepción.”

No arbitrary action names, AI prose, venue names, hostnames or raw errors. The design’s fixed action-name detail remains unavailable until P4 supplies its action vocabulary.
