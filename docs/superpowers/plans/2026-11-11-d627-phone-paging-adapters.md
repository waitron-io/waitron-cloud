**Interface and flow**

- `Notification` has `incidentId` and `notificationId` (UUIDs), `locale:'en'|'es'`, `service`, `affectedVenues` (nonnegative safe integer), `since` (strict UTC), and `fixProposed:boolean`. Reject extra fields. Configuration supplies synthetic recipient/senders, credentials, fixed incident HTTPS origin and explicit text-status/call-status/input callback URLs; build the incident link from origin and incident UUID, without tokens, query or fragment.
- Factories `createTwilioPaging(config):PagingProvider` and `createVonagePaging(config):PagingProvider` take required fetcher/timeout, recipient/sender/callback configuration and respectively account SID/token or API key/secret/voice JWT. `PagingProvider` exposes `text(notification):Promise<Submission>`, `call(notification):Promise<Submission>`, and `readTrustedEvent(kind:'text'|'call'|'input',body:unknown):ProviderEvent|null`. `Submission` is `{state:'accepted',id:string}` or `{state:'failed'|'unknown'}`; `ProviderEvent` is `{id,state:'delivered'|'failed'|'pending'}` or `{id,digit:string}`. Acceptance never means delivery or acknowledgement.
- `beginPage(notification,{twilio,vonage})` returns a per-notification in-memory handle after initial submissions. Send Twilio text, then call after text acceptance, without waiting for text delivery. A refusal or ambiguous submission starts Vonage text then call once. A refused backup text ends that route as failed; report the incomplete attempt honestly.
- The handle exposes `acceptTrustedEvent({incidentId,notificationId,provider,kind},body):Promise<void>`, `closeDeliveryEvidence(provider,kind:'text'|'call',id):Promise<void>`, and `result()` with separate text/call evidence and acknowledged flag. The caller invokes handle methods serially. Match context and resource IDs before any transition; ignore malformed, unrelated, duplicate and superseded-provider events. Retain only the two attempts for this handle, with no restart/replay guarantee.
- Before acknowledgement, a failed Twilio delivery event or caller closing still-unconfirmed evidence starts the single Vonage attempt. Backup failed/unknown delivery remains visible, without another attempt. Closing evidence is explicit caller input, with no wait duration or timer; late events cannot restart an attempt. Answered calls establish call delivery only. Only input exactly `1` for this handle's active matching call sets acknowledged; never infer it from delivery, ringing, answer, completion or a missing reply. Acknowledgement stops further dispatch from this handle.
- **Trust boundary:** `readTrustedEvent` and `acceptTrustedEvent` are local methods for an explicitly trusted caller, not authenticated webhooks. A future receiver must verify provider signatures and bind the callback route to this incident/notification before invoking them. Do not accept public HTTP here or claim operator authentication. The fake harness invokes these methods with provider-shaped events and supplies the callback response: empty TwiML `<Response/>` for Twilio input, empty NCCO `[]` for Vonage input, successful empty status responses. No polling endpoint is invented.
- Require injected `fetcher` and explicit credentials; never read environment credentials or fall back to global fetch. Keep provider API hosts fixed. Only test support maps those exact hosts to `127.0.0.1` random ports and rejects every other destination, retaining path, headers and body. Use redirect refusal, a 64 KiB response cap, fixed redacted errors and caller-supplied finite transport timeout capped at 10 seconds. Timeout/lost or malformed replies remain unknown; explicit refusals are failed. These request limits set no incident deadline.

**Provider mappings and primary references**

- Twilio: Basic SID/token authentication; form POSTs to `/2010-04-01/Accounts/{sid}/Messages.json` and `/Calls.json` on `api.twilio.com`. Text uses `To`, `From`, `Body`, `StatusCallback`; call adds inline `Twiml`, `StatusCallbackEvent=answered,completed` as repeated fields. Gather uses DTMF, `numDigits=1`, POST action URL and Say language `en-GB`/`es-ES`. Map `MessageSid`/`MessageStatus` (`delivered` confirms; `failed`/`undelivered` fail), `CallSid`/`CallStatus` (`in-progress` confirms answer; `busy`/`failed`/`no-answer`/`canceled` fail), and `CallSid`/`Digits`. Completion alone never acknowledges. Sources: [message](https://www.twilio.com/docs/messaging/api/message-resource), [call](https://www.twilio.com/docs/voice/api/call-resource), [Gather](https://www.twilio.com/docs/voice/twiml/gather), [future signature boundary](https://www.twilio.com/docs/usage/webhooks/webhooks-security).
- Vonage: Basic key/secret for form POST `https://rest.nexmo.com/sms/json`: `from`, `to`, `text`, Unicode type, delivery-report request and callback URL; `messages[0].status='0'` plus `message-id` means accepted. Voice POST `https://api.nexmo.com/v1/calls` uses caller-supplied Bearer JWT, phone `to`/`from`, `event_url`, inline NCCO talk then input (`type:['dtmf']`, `dtmf.maxDigits:1`, `eventUrl:[…]`; talk language `en-GB`/`es-ES`). Map text `messageId`/`status` (`delivered` confirms; `failed`/`rejected`/`expired` fail), voice `uuid`/`status` (`answered` confirms; unsuccessful terminal states fail), and input `uuid`/`dtmf.digits`. Other statuses stay pending. Configuration numbers use E.164; strip the leading plus for Vonage. Sources: [SMS](https://developer.vonage.com/en/api/sms), [voice](https://developer.vonage.com/en/api/voice), [input](https://developer.vonage.com/en/voice/voice-api/ncco-reference#input).
