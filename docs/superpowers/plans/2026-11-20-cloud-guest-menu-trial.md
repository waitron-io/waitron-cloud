# Require a trial or paid plan for guest menus

On the test Cloud, guests can open a venue’s shared menu while it has an active Connected or Hosted trial or paid level. The owner answered “Only with the trial” on 20 November at 14:13 in Lane K’s questions. This is slice 3 of setup pairing and works with existing boxes. Lane D owns the box preview. The plan covers `test-venue-levels`. Pairing, payment, production rollout and online ordering have separate work.

## Build and prove the gate

- **Billing and delivery.** In `packages/remote-access/src/guest-menu.ts`, use one read-only query for the venue’s billing authority, base level and trials, scoped by organisation, business and venue. Reuse `effectiveVenueLevel` via `packages/registration/src/index.ts` and the database UTC date. Treat absent authority as Registered and other environments as ineligible in this mode. Check after box proof, lease and the existing venue lock. Ineligible publish returns 403 `guest_menu_plan_required`. The successful reply to a signed status request adds optional `planRequired: true` only when ineligible, preserving the stored state for old boxes that withdraw. Lane D uses it to explain why sharing is unavailable and links to Billing. Withdrawal and takedown always remain available to authorised callers. Portal and test command **Allow sharing** clear the existing block to `off`. Guests still need an eligible publication to see a menu.
- **Public release.** In `packages/account-http/src/guest-menu-server.ts`, use that same query for eligibility and the stored menu’s state and revision together in the final check after buffering. GET and HEAD return the usual 404 if ineligible. Keep stored pages during a lapse. The same URL works when eligibility returns if the menu is still shared. Takedown and withdrawal still remove the pages. Wire the parsed mode through account-http `src/{app,guest-menu,server-cli}.ts` and `deploy/test-cloud/account-worker.mjs`.
- **Portal.** In `apps/portal/src/{remote-screen,locale}.ts`, reuse `connectedRequired`. Explain why the link is unavailable and use the existing Billing venue selection and **Start free trial** link when eligible to start. Otherwise offer Billing. Keep Stop sharing for a saved publication.
- **Tests.** In remote-access `test/guest-menu.test.ts`, prove a trial or paid level permits publish, a lapse committed during a venue-lock wait refuses publish, and withdrawal remains available. In account-http `test/guest-menu.test.ts`, assert the new refusal and optional status field. Keep the free-publication case in legacy mode and use eligible fixtures for test-mode publication cases. In account-http `test/guest-menu-server.test.ts`, expire eligibility while HTML is buffered and verify zero menu bytes, a 404 for GET and HEAD, and return of the unchanged menu when eligible. In `deploy/test-cloud/relay-runtime.test.mjs`, check a stored menu is hidden before trial, then start a trial and keep the existing successful publish and HTTPS read. In portal `test/guest-menu-browser.test.ts`, check the reason, trial link and Stop sharing in EN/ES, light and dark, at 390 and 1280 pixels.

Write the named failing cases first. Run them with `scripts/test-postgres.mjs` on the approved test runner, build the portal, inspect its browser captures and run `pnpm typecheck`.
