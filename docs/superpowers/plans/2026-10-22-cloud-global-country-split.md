# P3: Global identity and independent country services implementation plan

> **For agentic workers:** PLAN PUBLICATION ONLY. After separate owner plan approval and explicit build authority, use `superpowers:executing-plans` inline. Read the TDD skill before writing tests or implementation. Do not dispatch implementer/reviewer pairs. Publication, approval of this plan and permission to build are three separate steps.

**Goal:** You can operate Spain's venue services without Frankfurt, while accounts and fresh human authority remain global and no venue data enters the global layer.

**Architecture:** Keep identity in a separate global PostgreSQL database and venue state in a country database. Global signs narrowly bound control permits; countries verify them offline and combine them with country-owned permissions, revocation barriers and service duties. Move existing account state through a stopped, reconciled control-plane cutover, never through shared credentials or distributed foreign keys.

**Tech stack:** Existing Node >=26, TypeScript, pnpm 9.15.0, PostgreSQL, Hono, Lit, node:test, Playwright and Mailpit. Reuse `node:crypto` Ed25519, SHA-256 and existing authenticated encryption. Add no crypto, identity or provider dependency.

**Spec:** Read the COMPLETE [production design](../specs/2026-10-22-cloud-production-deployment-design.md), especially §§3/4/9/12, [seven-plan order](2026-10-22-cloud-production-deployment.md), [P1](2026-10-22-cloud-country-cell.md), [P4](2026-10-22-cloud-action-controller.md) and [documentation ownership](../../documentation-ownership.md). This plan implements P3, not the other six builds.

## Review focus

1. Revocation races a blocked operation: no stale authority escapes after the country barrier completes (Task5).
2. A caller guesses foreign account/organisation/venue/operation IDs: no read, mutation or saved result crosses scope (Tasks6–9/17).
3. A response is lost and an old nonce/body is retried: retain one operation, require fresh authority to disclose its result (Tasks5/7/13).
4. Mail is claimed during account changes or the split: keep recipient permission, ciphertext binding and delivery identity (Task11).
5. Transfer or restore stops halfway: never enable two identity writers or accept resurrected authority (Tasks15/16).

## Interfaces and authority decisions

New shared types live in `packages/identity/src/country-control.ts`; persistence/adapters live under new `packages/registration/src/global-country/`. `Id=string` UUID, `Digest=string` SHA-256 hex, `Utc=string` canonical ISO time, `Country=string` two uppercase letters; `DatabaseOwner='legacy-country'|'country'|'global'`. Define `SignedEnvelope={payload:string;signature:string}` here without importing registration into identity; `KeyObject` comes from `node:crypto`. These are proposed interfaces, not existing exports.

`ControlClaims={version:1;issuer:string;audience:string;country:Country;keyId:string;subject:Id;sessionId:Id;organisationId:Id;accountEpoch:number;sessionEpoch:number;membershipEpoch:number;permissionEpoch:number;platformPermissions:readonly string[];isOwner:boolean;canRegisterVenues:boolean;emailVerified:boolean;nonce:Id;issuedAt:number;expiresAt:number}`. Times are integer Unix milliseconds; epochs are positive safe integers. One org/country per permit, maximum **60 seconds**, expiry capped by the global session's actual idle/absolute deadline. Platform permissions are restricted to the closed country-control allowlist, never arbitrary caller strings.

No venue target, business operation digest or customer payload crosses to global. Country binds a cryptographically random nonce to `OperationBinding={id:Id;kind:CountryOperation;digest:Digest;organisationId:Id}` locally; global sees only the random nonce and identity/country metadata. Task12 defines `CountryOperation` as the exact closed registry of the existing human route/method pairs above, plus explicit P4 contract fixtures, not arbitrary shell/network instructions. Its digest binds the canonical method/path/body and local target identifiers, not just a caller-supplied digest string.

Use a dedicated canonical JSON array: domain string followed by the ControlClaims fields in their declared order, with sorted unique platform permissions. `{payload:string;signature:string}` uses canonical Base64url, Ed25519 DER SPKI/PKCS8 keys and SHA-256 public-key IDs, following existing `installation-proof.ts` primitives with separate keys. Limit decoded payload to 8192 bytes, signature to 64 bytes and trust to 8 keys. `signControl(claims:ControlClaims,key:KeyObject):SignedEnvelope`; `verifyControl(envelope:unknown,trust:ControlTrust,expected:{issuer:string;audience:string;country:Country},now:number):ControlClaims`.

Reject extra fields, noncanonical encodings, wrong key type/signature/version/scope, unknown/revoked kid, future issue time, issue time outside key validity, expiry beyond key validity, and `expiresAt<=now`; no network key discovery or caller-selected algorithm. Enforce deployment clock health, refusing fresh human admission if drift exceeds 5 seconds; do not add expiry grace. Task4's `ClockHealth={observedAt:number;offsetMs:number;source:string}` comes from an explicit local platform adapter; missing/stale (>60 seconds) health refuses new permits, while legacy and autonomous service clocks retain their existing rules. P1 must qualify the actual clock adapter rather than assume it exists.

`ControlTrust={generation:number;issuer:string;audience:string;country:Country;keys:readonly {id:string;publicKey:string;notBefore:number;notAfter:number;revoked:boolean}[]}` is an explicit pinned local trust bundle. Stage public keys in countries before switching global signer; keep old verification keys through all outstanding permits and transactions, then retire. A missing bundle/new kid refuses human control, never downloads keys. Emergency removal fences local permit rows under the same admission locks. Custody/restore must preserve trust generation, revocation epochs and used nonces; stale restored authority is quarantined until an explicit reconciliation, not served as current.

**Sessions:** Keep global opaque host-only cookies, 30-minute idle and 12-hour absolute expiry (`identity/src/sessions.ts`, migration002). Passive reads do not extend idle expiry. Every country human request, including reads/retries, performs a new explicit browser control exchange using the existing global session and CSRF. Countries never accept that cookie or create independently refreshable human sessions. During global loss an existing global session remains stored but cannot refresh, mint new permits or start recovery; expiry keeps advancing. A permit already issued may finish only its existing bound operation before its own deadline and local revocation fence. A recovery already committed uses its existing bounded country operation/machine proof, never a new recovery approval.

**Revocation without a false freshness promise:** Offline signature verification cannot discover an unseen global change. Use a durable barrier, not a claim of instant cross-country revocation. Global session/account/member/permission changes first mark the relevant authority epoch `closing`, deny new permits and record an identity-only control exchange to every country with an issued binding. Each country locks its local authority rows exclusively, cancels outstanding human permits and invalidates affected consent/delivery/support grants as required, then records an ACK. Ordinary human operations hold shared authority locks through final recheck/commit, so ACK waits for admitted work. Global reports the security change **complete only after every ACK**; unreachable countries mean visible pending, with new authority denied. Token expiry alone is not an ACK or evidence an in-flight transaction finished. Already committed effects remain facts. Do not hold a global SQL transaction across HTTP or use two-phase commit.

Retries of that explicitly initiated exchange are allowed; no background venue operation may initiate one. Global keeps only account/session/org/country/epoch/nonce/receipt-state records, never venue identifiers, payload hashes or results. Separate country authentication signs bounded ACKs and metadata installation; reject wrong country, backwards/skipped epochs and changed duplicates. New grants wait for all relevant epochs to be installed. Country bindings contain account/org/country identity scope only, with no venue count or directory. A new binding installs current epochs before it can accept a permit, including when it races revocation.

Session logout/reset/factor/session-revoke fences human permits for the affected sessions; it does **not** cancel durable service consent. Account disable, lost verified email or owner membership loss also fences the affected account-derived relay/translation/alert/support authority. Permission removal fences only matching operator/support authority; registration-flag loss fences registration permission. None revokes an unrelated installation or kills a trading server. Preserve existing atomic global credential/session/outbox changes, with a visibly pending response until the relevant country barriers finish. A successful reset never claims its old country authority is already fenced when it is not.

`HumanAuthority.resolve(client:PoolClient,credential:string,proof:{csrfToken?:string;touch?:boolean}):Promise<{accountId:Id;expiresAt:Utc}>`, `membership(client:PoolClient,accountId:Id,organisationId:Id,need:'member'|'owner'|'register'):Promise<void>`, `permission(client:PoolClient,accountId:Id,name:string):Promise<void>`, `current(client:PoolClient,credential:string):Promise<void>`. Provide separate `legacyHumanAuthority` and `CountryHumanAuthority`; never sniff a string and silently fall back. Country resolution reads only signed claims plus locked local authority rows. No country `cloud_credentials`/`cloud_sessions` compatibility mirror survives retirement.

`CountryControl.run<T>(envelope:unknown,binding:OperationBinding,work:(client:PoolClient,credential:string)=>Promise<T>):Promise<T>` owns one transaction: verify/lock authority, match the nonce's local binding, recheck current epochs/time, run the supplied-client store core, final recheck, consume permit and save result/audit atomically. The credential is a random transaction-local handle, bound to that client/verified actor, never a reusable bearer token. Repeated nonce/same binding cannot execute twice; changed binding conflicts. A retry reading a saved private result needs a fresh permit/current authority. Add supplied-client + explicit human-authority options to affected stores; nested human methods cannot open another transaction or consume a second permit.

External DNS/object/recipient checks remain outside SQL locks, as existing code requires. Persist/reuse the country operation identity, perform that bounded preparation first, then use a fresh permit for final commit and revalidate its result/target generation. Never wrap current `setHostname` DNS callbacks or backup object transfers in a transaction spanning network work. Keep legacy entrypoints working; trusted account-ID shortcuts are unavailable in split runtime. Saved results contain no raw recovery keys, credentials or storage grants: reproduce secret-bearing responses only through the existing fresh bounded machine/authority flow.

**Autonomous duties:** Country installation keys/leases, route/certificate signing, backup capture/storage credentials, job claims, configured services and admitted P4 commands remain local. Preserve their actual expiries, revocations, configuration revisions, policy, quotas and consent. Human permits cannot renew themselves or become a service grant. Account-derived relay/translation/delivery grants require a country authority row installed by an explicit control exchange; completed disable/member loss/withdrawal fences it. No increased expiry or fallback grants. Existing machine renewal can continue from its country installation key after its one-hour lease expires, as today's `InstallationStore.execute('renew')` allows; global outage is not revocation.

Cutover order is explicit: freeze legacy human controls/identity writers; stage/verify G with its API/identity worker disabled; install C projections and apply C046 using the detached manifest; switch country consumers to its owner marker and record the country ACK; only then enable G identity writes/mail via the matching checkpoint. The two markers need not commit atomically because the ordered protocol always permits a safe waiting state. Country machine writes never enter the global export.

After C046, never restore the stale mixed identity copy or old binary as an automatic rollback. A compatible split binary may roll back against current ledgers/data; incompatible changes repair forward. **Before C046 only**, you may discard staged G and resume legacy account writes. After that boundary, reverse transfer needs its own stopped, lossless reconciliation and explicit authority; P3 does not implement one. Venue/fiscal records never move or rewind, and fiscal trading on a new schema/version never permits data rollback. Backup/restore both databases with matching external keys/authority markers; restored stale C cannot accept old human permits until reconciled.

## Execution tasks

Tasks target 30–65 tool calls each, always below 100; split at a passing deliverable before 75. Use named behavioral RED first, observe the expected missing-feature/assertion failure, then minimal implementation and the same GREEN command with nonzero counts/no skips. Import errors are only initial scaffolding RED; also observe the behavioral failure before adding each critical guard. Every task ends `git add <only task paths>` and `git commit -s -m "<task message>"`, with hooks enabled. Prove each listed guard by omitting it alone in an installed disposable copy and observing its original test fail; keep receipts outside Git. Preserve existing behavioral tests in legacy mode and add equally strict split tests, never rewrite security assertions to make new code pass.
