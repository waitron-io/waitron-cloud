# Send short staff notices through Cloud email

When a venue chooses Cloud email and has no saved mail server, staff can receive six more notices in English and Spanish. Cloud writes each subject and message. The box still decides whether to notify someone and which address to use. This branch supplies Cloud's side. Lane D supplies the box side and records the joint synthetic mail check.

## Signed request

Use `version: 2` for the six new classes on `email-submit`. Keep the existing `messageId`, `grantId`, `grantRevision`, `class`, `recipient`, `displayName` (the venue), `locale`, `timeZone` and `expiresAt`. Add one `facts` object with exact keys. Keep the 4,096-byte cap, existing recipient, locale and zone validation, and the 24-hour Cloud deadline. Lane D caps the submitted deadline at the earlier of the notice's existing deadline and 24 hours from signing. Instants use UTC ISO strings. Calendar days use real `YYYY-MM-DD` dates. The venue name uses the existing bound. The box trims editor, role, person and device labels to 80 characters. Cloud validates those bounds and uses the labels only in the plain-text body. Cloud rejects extra keys, including caller-supplied wording, headers and links. [Existing wire exchange](../../transactional-email-relay-contract.md#proposed-wire-exchange)

| Class | Facts |
| --- | --- |
| `email_changed` | `editorName`, `at`. The recipient is the old address. The new address is omitted. The separate security notice keeps the current recipient the box selects. |
| `security_change` | `at` from the queued time and `change` from `password_changed`, `passkey_added`, `passkey_removed`, `authenticator_set_up`, `authenticator_removed`, `recovery_codes_regenerated`, `email_changed`, `google_connected`, `google_disconnected`. |
| `role_membership_changed` | `change` (`added` or `removed`), `editorName`, `at`, and either `builtInKey` (`staff`, `supervisor`, `manager`, `admin`) or `roleName`. |
| `box_alert` | `code` plus the exact facts listed below. |
| `certificate_reminder` | `date` in the venue's zone and `stage` (`due` or `expired`). For `due` only, add nonnegative integer `daysLeft`. The box maps warning and urgent to due using its existing calendar calculation. |
| `attendance_question` | `businessDay` and `missingKinds` (one or both of `in`, `out`, without repeats). Tell staff to correct their hours at the next clock-in. |

- `storage.space_low`, `storage.disk_full` and `clock.unusable` take only their code.
- `backup.archives_deleted` adds positive integer `count`, `date` and `lastDate`. Cloud uses the date range when the days differ. `backup.run_stopped` adds nonnegative integer `neededBytes` and `availableBytes`.
- `upgrade.rolled_back` adds `fromVersion` and `toVersion` as Waitron release labels of up to 50 characters. `clock.corrected` adds `before`, `after`, `beforeOffsetMinutes`, `afterOffsetMinutes`, signed integer `stepMs`, `source` (`admin`, `staff`, `setup`) and boolean `unverified`. Offsets are whole minutes within ±14 hours. Use the step's sign for direction. On verified corrections accept optional `person`, and on verified staff corrections accept optional `device`.

Invitations, password resets, email-change codes, status, cancel, replies and grant discovery keep version 1. Reuse signing, grant checks, encryption, exact replay and worker handoff. In the pilot, each notice uses a unit from the same allowance as account email. The current local pilot allows three per account per hour, so a batch can delay or exhaust account mail. Use synthetic venues and prove behaviour at the existing limits. [Pilot settings](../../../deploy/test-cloud/relay-settings.mjs)

The watcher's clearance must settle the pilot consent scope before either side builds. The current setup describes the three v1 classes. The proposal is to name the added notices in setup, use the existing grant for freshly opted-in synthetic venues and leave existing venues on v1 during the joint check. The watcher also needs to confirm the attendance question named in the queue against the earlier free-service wording.
