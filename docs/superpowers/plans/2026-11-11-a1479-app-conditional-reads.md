## One bounded change

- Modify only `scripts/disposable-tests/github-app.mjs`, `scripts/disposable-tests/github-app.test.mjs`, `scripts/disposable-tests/publication.test.mjs`, `deploy/disposable-tests/README.md`, `docs/backlog.md`, and this plan.
- Keep `GithubApp`'s public API. Add a private in-memory cache per instance, bound to its configured App and exact request URL including query; never share between client instances or retain credentials as cache keys/data. Token renewal reuses that configured App; credential rotation is outside this slice.
- Cache only authenticated JSON GETs. Every call still fetches; send the saved ETag as `If-None-Match`. Capture the matching ETag/body together before awaiting fetch. Handle 304 before the `!ok` refusal and release its body; accept it only for that captured entry, otherwise fail visibly.
- On 200, enforce the existing 2 MiB response bound and parse JSON successfully before replacing the entry. Store private body bytes and parse independently for every return, including the initial 200, so caller mutation cannot change later results. Preserve empty-body `null` without caching it.
- Cap at **64 entries and 4 MiB total body bytes**; refresh recency on every successful use, including 304, and evict the least recently used until both bounds hold. Thirteen clients retain at most52MiB of body bytes, plus metadata/transient parsing. The sampled30URLs exceed the first draft’s16-entry cap; no cap promises every busy controller URL stays cached.
- A successful response without ETag removes any older entry and remains unconditional next time. HTTP errors, malformed/oversized/interrupted bodies and fetch failures still fail; never serve expired or stale data on error. A later successful conditional revalidation may reuse its matching body.
- Never cache tokens, credentials, mutations or job-log downloads. Preserve deadlines, cancellation, path/origin checks and primary/secondary backoff. No persistence or cross-process service.
- Keep `requests` meaning actual fetch attempts, including 304. Require a `notModified` count in each existing minute bucket and retain raw `limit`/`used` alongside its current quota snapshot; no new event system. Workers start cold and save mainly on monitor reads; admission and token costs remain.
