# Keep Cloud's test inbox independent of reverse DNS

The watcher queued MAILPIT-SEND-REJECT on 18 November at 23:05. Package tests should be able to deliver mail to their local Mailpit inbox even when a DNS server fails to answer. Both [pull request CI](https://github.com/waitron-io/waitron-cloud/actions/runs/44401032178/job/135144301324) and [merge CI](https://github.com/waitron-io/waitron-cloud/actions/runs/44404647763/job/135156758305) recorded a five-second send failure and a pending outbox row. Both downloaded job logs are saved in the lane’s `receipts/mailpit-send-reject` directory. They do not show which part of SMTP stalled.

On the Debian test box, a private DNS listener received reverse lookups and deliberately sent no answer. Mailpit v1.31.1's HTTP inbox was ready, but it sent no SMTP greeting and the real local mailer rejected after 5,037 ms. Disabling that lookup gave a greeting in 33 ms and an accepted message at 84 ms, with zero DNS queries. A second test ran through the unchanged `scripts/test-postgres.mjs`. Both a sign-in check and an owner handover had failed by 5,068 ms while the inbox still answered HTTP 200. The probe and its output are in the same directory. This establishes the cause in the controlled run. The original CI failures lack the detail needed to confirm their cause.

1. In `scripts/ci-test-postgres.test.mjs`, add “launcher disables reverse DNS only for the Mailpit container”. Reuse `launch(t)` and select the Mailpit and PostgreSQL `run` arguments from `result.invocations`. Check that only Mailpit gets the argument pair `--env MP_SMTP_DISABLE_RDNS=true`. Run it by name before changing the launcher and observe it fail on the absent Mailpit argument.
2. Add that setting to Mailpit's existing `docker run` in `scripts/test-postgres.mjs`. The change is local to the package-test launcher. Keep the SMTP client deadline, mail assertions and deployment fixtures out of this change.
3. Run `node --test scripts/ci-test-postgres.test.mjs scripts/ci-workflow.test.mjs`. Repeat the controlled Linux launcher test and require that both real messages arrive while DNS is unresponsive. On Linux, run `pnpm --filter @waitron-cloud/portal build`, then `node scripts/test-postgres.mjs exec node --test --test-timeout=120000 apps/portal/test/account-action-proof-browser.test.ts apps/portal/test/owner-transfer-browser.test.ts`. This checks for regressions in the two reported browser journeys. Keep the forced-DNS setup in the lane receipts.
4. Record the controlled failure, setting and receipts in `docs/backlog/mail-capture.md`. If the failure recurs, capture which SMTP stage timed out before attributing it to a cause. Link from the portal boundary-reporting entry in `docs/backlog.md`. Leave the separately reported reset-mail investigations open.
