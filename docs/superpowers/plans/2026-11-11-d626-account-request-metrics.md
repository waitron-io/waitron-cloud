## Smallest build

Reuse `server.ts`’s Node listener/Hono adapter, admission and portal selection; the collector’s polling/freshness; `operations-health.mjs`’s transport; fixed-label formatting conventions in `packages/operations/src/metrics.ts`. This is source assessment, not execution evidence.

- Add `packages/account-http/src/request-metrics.ts`: finite accumulator, bounded JSON snapshot validation and Prometheus formatting, imported directly by the collector. Groups: `health`, `account`, `installations`, `relay`, `portal`, `other`, `parser`; use decoded segment boundaries and existing portal precedence. No raw URL, query, ID, token, Host, email or exception label.
- Outcomes: `success` = 2xx/3xx; `refused` = 4xx except 408; `server_error` = all 5xx, including admission/shutdown 503; `timed_out` = 408 or `ERR_HTTP_REQUEST_TIMEOUT`. Existing wire answers stay unchanged.
- Export `waitron_cloud_account_requests_total` and `waitron_cloud_account_request_duration_seconds_{bucket,sum,count}` by group/outcome; cumulative bounds 0.05, 0.1, 0.5, 1, 5 seconds and `+Inf`. These are measurement bands, not targets. Export only observed pairs. Carry `startedAt` in the snapshot and export `waitron_cloud_account_requests_started_timestamp_seconds` so restarts can be detected between readings.
- Time from Node request admission until response `finish` using a monotonic clock, including early refusals and adapter failures. `clientError` settles an associated unfinished request once; without a parsed request, increment only `parser` counts, with no invented duration. Share settlement guards; keep-alive requests remain distinct and closed sockets are not retained. Exclude disconnects without a completed response or observed timeout; histogram counts can therefore differ from request counts.
- An optional separate read listener owned by `startAccountServer` serves exact `GET /metrics` as bounded JSON with `no-store`, other requests 404, and excludes its own scrapes. `server-cli.ts`: strict `CLOUD_LOCAL_REQUEST_METRICS=0|1`, default off, refused in production. The local account CLI enables container `0.0.0.0:9092`; no host publication, public account route, ingress or Compose change. Close both listeners and clean up partial startup. Test Cloud reuses the account environment but its direct worker does not consume this CLI flag (`deploy/test-cloud/runtime.mjs:14`, `account-worker.mjs:49`, source-only); LAN collection remains excluded.
- Extend `operations-health.mjs`: fixed `http://account:9092/metrics`, two-second deadline including body, 16 KiB bound, status/JSON/schema checks, no redirects. The collector fetches, validates and formats counts in its own existing poll, independently of the operations sample. `/status` and `operations-sample.mjs` remain unchanged. Counter acquisition failure preserves operations status, omits request series and exports `waitron_cloud_account_requests_available 0`; valid counters export 1. Existing failed/stale collection suppresses old request series too. General operations CLI/readiness unchanged.
