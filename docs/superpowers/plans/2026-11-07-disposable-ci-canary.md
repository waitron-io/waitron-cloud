# D592: first single-slot CI job

This amends [slice 3](2026-11-06-disposable-test-server.md) of the [approved design](../specs/2026-11-06-disposable-test-server-design.md). Lane I questions.md, WATCHER 7 November 12:04: “the first Cloud jobs running on the server, falling back to GitHub when it is down”; “Do multiple test slots and capacity measurement after that”; “No new controller, ledger or recovery work beyond what the runners need.” The [restart check is complete](https://github.com/waitron-io/waitron-cloud/pull/1061#issuecomment-6706129609).

- [ ] Add non-required `disposable-ci-canary.yml`: hosted-default workflow dispatch, unchanged eight-minute typecheck workload, hosted summary, bounded pnpm setup, no caches or persisted checkout credential. Keep ordinary CI unchanged. Separate the reviewed workflow blob/digest at run head from the source commit supplied as input; independently check its tree and actual checkout. Derive routing labels from GitHub run ID, attempt and YAML job key; authorize the concrete numeric job ID from the API. Preserve the design’s identity checks and public-repository risk: labels cannot prevent another approved workflow stealing the runner.
- [ ] Add `ci-canary.mjs` through the trusted Mac entry point, holding its existing kernel lock before dispatch. Dispatch and poll only its own canary; no webhook service or broad cancellation. Persist the runner name and run/attempt/job/source identities in an optional validated `ci` lease field before registration. `leases.mjs` preserves local fields and assertions. A lost registration response reconciles by saved name without reminting. Extend only background `manual.mjs --once` recovery to remove that runner using the configured Mac App, destroy/inspect the exact guest, and release after both absences. Ordinary occupied calls still return 75. Missing App access or uncertain cleanup keeps the slot closed.
- [ ] Give `session.py` a validated CI preparation mode: no source archive, private-package download or pnpm install. Install the checksum-pinned runner during guest preparation; qualify disabled automatic updates. The CI maintainer bumps the pin when GitHub requires it. Extend `transport.mjs`/`guest-exec.py` to stream bounded JIT configuration through stdin and memory into the guest runner’s environment, never bundle/control files, Mac/shared-host argv or logs. Job code can access its own transient inputs; destruction removes them. Prove the pinned runner actually consumes and clears that environment input.
- [ ] Activation waits for the supplied single Mac App handoff and existing contributor/risk gates. Read-only `gh api repos/waitron-io/waitron-cloud/actions/permissions/fork-pr-contributor-approval` reported `all_external_contributors` on 7 November; recheck and retain the returning-contributor refusal drill. No durable credential goes to the server. Prove cold install with the job’s read-only package token.
- [ ] TDD identity/replay/assignment refusals, lost response, secret handling, controller death, stale cancellation, server-down and independent runner/VM cleanup. Preserve all existing queue/poll/cancellation/cleanup/execution bounds and documented Mac-down 24-hour limit. Direct server dispatch without this controller has that same queue limit. Import owning cases into the aggregator; run `node --test scripts/ci-disposable-local.test.mjs` once. Prove actual assignment/head/tree/attempt/summary, visible failure and explicit hosted redispatch of the identical source. Update README/backlog. Ordinary mode-variable rerun evaluation, mixed capacity, multiple slots and Waitron remain later gates.
