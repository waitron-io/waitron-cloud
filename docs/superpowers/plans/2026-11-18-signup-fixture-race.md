# Keep verification mail tied to its test signup

The owner-transfer tests can create two sender accounts at once and each sender can complete its own signup. CI run 44401032178, job 135144301304, failed with `verification_unavailable` when the fixture used the newest row for both. The watcher's 22:40 note in lane G's questions file assigned a test-only fix: “both helpers pick the verification row for THEIR recipient, not the newest across all recipients, with the forced-interleave case that failed first.” The 23:48 note queued it ahead of MAILPIT-SEND-REJECT.

1. In `packages/registration/test/owner-transfer.test.ts`, split the account fixture into queuing a request and returning a function that completes it. Let `signedAccount` accept that completion function and keep ordinary calls immediate. In “verified first-time signup attaches every live offer without creating business access or a session”, queue both senders before either completion runs, then complete them concurrently with their existing sign-in and proof setup. Keep every handover assertion. Run the case against PostgreSQL with the old lookup and record the `verification_unavailable` failure in the PR.
2. In `packages/account-http/test/fixtures.ts`, add one shared lookup using `signup_requests.email` to match the normalized fixture address and the token hash to join to its verification outbox row. Require exactly one row and open it with the fixture's existing outbox. Both account fixtures request once per unique address. Use the lookup in the account creation helpers of `packages/registration/test/owner-transfer.test.ts` and `packages/account-http/test/owner-transfer.test.ts`. Keep the other mail lookups and runtime code out of the patch.
3. Run both owner-transfer files through `node scripts/test-postgres.mjs exec node --test --test-timeout=30000 packages/registration/test/owner-transfer.test.ts packages/account-http/test/owner-transfer.test.ts` on the campaign test box. Record the passing cases in the PR. Reverting the recipient match in a disposable checkout should make the forced case fail again.
