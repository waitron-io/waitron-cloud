# Translation interruption proof implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan inline, task by task. Steps use checkbox (`- [ ]`) syntax for tracking. The owner has already supplied autonomous design, implementation, finish and land authority; do not add an interactive approval gate.

**Goal:** Prove the four D85 interruption cases against the real Cloud and Waitron HTTP servers, including independent SIGTERM and SIGKILL restarts.

**Architecture:** Extend the in-process Cloud test fixture with a small page budget, request pauses and actual socket reply loss. A Cloud script pairs a disposable real Waitron server, creates synthetic content through management routes, runs the real Cloud worker against its fake provider, and checks HTTP, read-only SQLite and Cloud PostgreSQL evidence. Keep all Waitron source and campaign writes outside this implementation.

**Tech stack:** Node 26+, JavaScript/TypeScript, node:test, Playwright Chromium, PostgreSQL/Mailpit through `scripts/test-postgres.mjs`, read-only `node:sqlite`, the existing Waitron fixture and background runner.

**Spec:** [Translation interruption proof](../specs/2026-10-19-translation-interruption-proof.md). Read it whole, especially the acceptance table and notification ordering.

## Review focus

- A response using `write` as well as `end` must still be completely suppressed on loss; the original bounded request reader must see unchanged bytes. Task 1 tests actual sockets and streamed response writes.
- Cancelled or closed fixture gates must never run delayed work or leave sockets/processes alive. Task 1 exercises cancellation and Task 3 exercises failed-case cleanup.
- The small budget must not change normal fixtures or permit a larger production page. Task 1 tests default behavior, rejected limits and two simultaneous fixtures with different budgets.
- Observing progress must not acknowledge the finished run before its notification is tested. Task 3 checks a real alert/bell before its final suggestions GET.
- A stopped process may have a null exit code and a nonnull signal; cleanup must reap it without signalling a reused PID. Tasks 2 and 3 test both exit forms, generation-scoped traces and final cleanup.

- Append `translation?: {pageBytes?: number}` as `startPortalFixture`'s fifth argument. Omission retains the existing translation-off fixture. `{}` enables a default-budget test machine; `{pageBytes:512}` enables the small-budget one. Only that opt-in fixture returns a usable `translation` controller, which lives in the new test helper.
- Controller: `pauseCollect(cursor: number)` returns `{entered: Promise<{jobId:string;cursor:number}>, resume():void, cancel():void}`; it pauses once before delegating `execute` and outside a transaction. `loseReply(action: 'translation-collect'|'translation-release', cursor?: number)` arms one real HTTP loss and returns `Promise<{status:number;body:string}>`. Calling it arms the loss immediately; await its promise after the operation. All controllers are disposed by `f.close()`.
- Controller: `beforeRelease(check: (jobId: string) => Promise<void>): () => void` registers an awaited check before each release delegates, outside its transaction; the returned function removes it. Record callback failures for the script to fail immediately instead of silently retrying a failed assertion. Dispose the callback on fixture close.
- Controller `events` is an ordered array of records with `kind:'request'|'reply'|'lost'`, `action`, `jobId`, optional numeric `cursor`, and, for replies/losses, `status` and parsed `body`. Requests are recorded before any gate; replies reflect actual HTTP serialization. Script-owned generation markers identify which child issued requests. Keep envelopes/credentials out of events. Helper internals and names other than this surface are the builder's choice.
