# D621 email delivery after database failover

When a database machine stops, a worker on a surviving machine should send sign-in mail as soon as it can use the new primary. In the free Kind rehearsal, both workers exited on idle connection loss. After PostgreSQL was writable, the first fresh message spent 31.234 seconds queued, including 26.621 seconds when both workers were down. Kubernetes reported 10- and 20-second restart delays. The message submitted after 75 seconds went out in 0.090 seconds. The earlier late message spent 0.271 seconds queued. Stockholm's late row with zero attempts remains unexplained.

- In `packages/registration/src/email-worker-cli.ts`, keep the default worker running through idle connection loss and retry failed database polls through the existing `runWorkerLoop` one-second wait. Keep one-shot `--once` and `--status`, signal-driven drain, claims, mail retry rules and probes as they are.
- In default mode use the pool's awaited `onConnect` hook to run `checkConsumerSchema` from `deploy/local-stack/runtime.mjs` on each new connection before it can claim mail. Resolve it from the installed module path, as the schema compatibility test does. Log a fixed message and reject an incompatible connection. Keep the existing deployment startup check.
- In `packages/registration/test/email-worker-reconnect.test.ts`, use real PostgreSQL and the existing loopback SMTP fixture. Terminate tagged idle connections in one case and tagged queries blocked on an outbox lock in another. In each case the same worker process must send a fresh row. Test a changed migration digest on reconnect and wait for the explicit refusal before reading attempts and captured mail. Restore the digest and verify delivery. Observe each new case fail before adding its fix.
- Run the focused reconnect, `email-worker-shutdown.test.ts`, `local-mailer.test.ts` and `schema-compatibility.test.ts` cases through `scripts/test-postgres.mjs` with `--test-concurrency=1`. Also run `deploy/local-stack/schema-consumer.test.mjs` and `pnpm typecheck`. Replay the same free primary stop, record restart counts on both survivors and measure the first fresh send against the writable-database time. Update `docs/backlog.md` with what the rehearsal proves and the open Stockholm question.
