# D621 email delivery after a database connection drops

A surviving worker should send fresh sign-in mail after it reconnects to PostgreSQL. In the free Kind rehearsal both workers exited on idle connection loss. The first fresh message spent 31.234 seconds queued after the database could take writes, including 26.621 seconds with both workers down. The other 4.613 seconds covered failed startup checks still in progress and the final startup and send. Kubernetes reported 10- and 20-second restart delays. The earlier 49.716-second delivery lacks precise restart times. The earlier 76.450-second delivery followed deliberate submission at 75 seconds and took 0.271 seconds from queue to send. The experiment cannot show whether Stockholm's workers exited, hung or stopped polling.

- In `packages/registration/src/email-worker-cli.ts`, apply recovery only to the default command. Log idle connection loss and let the pool replace dead connections. Retry rejected passes through `runWorkerLoop` and its one-second wait. During shutdown keep failures fatal, including idle errors, and keep `--once`, `--status`, claims, mail retry rules and probes unchanged.
- Use the pool's awaited `onConnect` hook in the default command to run the existing `checkConsumerSchema` on the new client before it can claim mail. Resolve the module and root as in `cloud-action-cli.ts`. Log a fixed schema refusal and exit 1 on `schema_incompatible` so the existing startup check continues to refuse the incompatible worker. Connections that remain open and silent need a separate test.
- In `packages/registration/test/email-worker-reconnect.test.ts`, use real PostgreSQL and the loopback SMTP fixture. Terminate tagged idle connections in one case and queries held on an outbox lock in another. In each case require the same process to send a fresh row. For schema refusal, change a migration digest, end every tagged connection, then queue mail. Wait for exit 1 and the refusal before checking zero attempts and no captured mail. Restore the digest and verify a new worker can send the row. Observe each case fail before adding the corresponding change.
- Run the reconnect, email worker shutdown, natural exit, local mailer and schema compatibility files through `scripts/test-postgres.mjs` with `--test-concurrency=1`. Run `deploy/local-stack/schema-consumer.test.mjs` and `pnpm typecheck`. In the same free replay, require zero restarts on both survivors and a fresh send within 10 seconds of observed database write availability. Update `docs/backlog.md` with the timings and the open Stockholm question.

Estimate 25–40 code lines and 110–150 test lines. The watcher clears the plan before implementation.
