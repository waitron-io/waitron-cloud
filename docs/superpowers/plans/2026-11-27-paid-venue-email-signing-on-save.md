# Set up venue email signing after owner save

In test Cloud, a Connected or Hosted owner saves a sending address and publishes the DNS alias returned by the portal. With signing enabled for that test domain, Cloud sets up and verifies signing once the alias resolves. Rehearse through normal worker startup with fake providers. Sending from the venue address and fallback are the next slice. [Cloud plan](2026-11-25-paid-venue-email-cloud.md#2b-show-verified-domain-records)

Run signing in the existing test email worker so its provider calls can wait for DNS changes independently of save and **Refresh status**. A Route 53 change can take 75 seconds (`packages/remote-access/src/route53-dns.ts:11)). The tick still reports alias resolution.

Require the same suffix, SES region, Route 53 zone and test-domain allowlist as the operator command. Share input validation with `packages/remote-access/src/venue-mail-signing-cli.ts`. Validate before constructing the existing provider adapters. Use temporary fake adapters in the local proof. Live credentials and provider calls require separate approval.
- In `email-worker.mjs`, use `runWorkerLoop` with one signing slot and `pollIntervalMs:60000`. The pass always reports no queue work, including in one-shot mode. A failed venue or listing query logs the venue or step and leaves the mail queues running. Stop starting signing attempts on shutdown and let any active attempt settle while the process has time.
- In `packages/remote-access/src/venue-mail-signing.ts`, list saved test choices on the domain allowlist, plus saved test choices for venues that already have a claim, ordered by venue ID. Run the [existing signing operation](2026-11-27-paid-venue-email-signing.md) once per venue for eligibility, exact DNS and key checks, and holds after uncertain writes. A changed domain can retire the same venue's old claim and provision on a later pass. Reset, deleted venues and held claims use the existing per-venue command and [operator procedure](../../test-cloud-service-controls.md#investigate-held-venue-email-signing-cleanup). General stale-claim listing, key rotation and portal signing status are outside this slice. Rechecking a verified venue makes provider reads each pass. Review that cost before any live use.
