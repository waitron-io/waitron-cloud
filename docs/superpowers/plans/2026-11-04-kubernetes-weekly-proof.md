## Components and why each remains

| Component | Why it exists; what fails without it |
| --- | --- |
| One setup template and thin `up`/`down` entry | Generates roles, private network, storage, launch template and expiry protection together; otherwise setup becomes the rejected owner resource-shopping exercise. |
| Temporary GitHub OIDC launcher role | OIDC exchanges GitHub's identity for a short AWS session; without it runtime needs stored keys. Owner bootstrap permissions never reach runtime. |
| Private subnet, empty-ingress security group and S3 gateway endpoint | Keeps the guest unreachable from the internet while allowing bounded offline transfer; without this path private execution lacks its inputs/results. |
| One private S3 bucket plus conditional ledger | Carries offline bytes/results and serializes spending across retries/months; workflow concurrency alone loses reservations when its controller disappears. |
| Machine's fixed systemd (Linux service manager) deadline | Powers off even when proof/launcher hangs; without it ordinary controller loss relies entirely on an AWS delivery path. |
| One-minute EventBridge rule, Lambda sweeper and its execution role | Finds tagged instances even after a lost launch response and terminates despite failed bootstrap/kernel hangs; an OS timer cannot cover these failures. Rule invokes Lambda through its resource policy, without another invocation role. |

Remove the per-instance Scheduler, its termination role, schedule reconciliation and runtime `iam:PassRole`: the already-armed sweep covers kernel/controller loss and unknown launch IDs. Two independent termination actors remain, with separate real drills below. Delayed/failed AWS delivery, EC2 failure or incorrect bootstrap can still delay cleanup and billing; uncertainty blocks new spending rather than promising failure-proof billing.
