## Review focus

- Timer and graceful-stop readiness together: no cycle starts after the admission boundary.
- A DB initialization cycle starts its replica during drain: every resulting goroutine is joined.
- Retention/retry/pagination continues after drain starts: admitted work completes and remains counted.
- Control timeout, concurrent drain or another control route: no success acknowledgement, restart or leaked producer escapes the terminal state.
- A valid version string with the wrong executable, platform or patch: refuse before workload execution.

## Task 2: implement and prove native graceful drain

- [ ] Begin with `TestDrainEndpoint` in upstream `drain_test.go`, using the existing server/HTTP interfaces against unpatched source: expect the specified acknowledgement and observe HTTP 404. Then add `TestDrainHeldReplicaPut`, `TestDrainHeldRetentionChain`, `TestDrainBeforeTransportAdmission` and `TestDrainTimerAdmissionRace` in separate RED/GREEN cycles. Gate real HTTP replies/cycle entry deterministically, not with sleeps. Assert no cancellation or acknowledgement before release, follow-up requests complete, then all producers join and no storage request starts after acknowledgement, even when timers fire. Run `go test -race . -run '^TestDrain'` in CI for each cycle.
- [ ] Add RED `TestDrainLazyReplicaStart`, `TestDrainFinalFlush`, `TestDrainConcurrentControls`, `TestDrainDeadline` and `TestDrainRepeatedClose`: cover a replica created by an already-admitted initializer, last WAL frames, concurrent sync/start/stop, silent backend and repeated drain/Close. Add `TestDrainRecovered503` to preserve successful retry behavior with all attempts counted. Require unrecovered errors to prevent success, deadline refusal and complete owned cleanup. Do not require a failed/cancelled session to reconcile successfully.
- [ ] Implement a synchronized terminal lifecycle and background-cycle admission gate in `drain.go`. Integrate graceful wakeups at store/DB/replica wait and cycle boundaries, including lazy starts. Leave accepted cycles' contexts alive and join them before final flush/DB close. Ensure final flush cannot start background monitors; retain every accepted request chain and propagate errors. Returning from later Close must do no storage I/O after successful drain.
- [ ] Implement the bounded private socket endpoint in `server.go`; reject unsupported producers/configurations and concurrent storage controls. Timeout transitions to failure, never drained. Cancellation for failure cleanup must not be confused with success. Run the native RED commands to GREEN and upstream affected close/sync/store/replica/server tests under `-race`, with counts and logs retained by CI.
- [ ] Delete each admission check, lazy-start join, active-cycle join, final-flush error check and success-reply guard in disposable copies.
