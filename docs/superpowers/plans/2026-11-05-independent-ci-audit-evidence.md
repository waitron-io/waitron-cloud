# D577: Independent CI audit evidence, design and implementation plan

> Execute inline with `superpowers:executing-plans` and TDD after the controller obtains one fresh-context design review and lands the design and measurement documents first. The controller owns review and publication; this authoring session changes only this document. Implementation requires the FULL Claude run-it review, normal hooks and exact-head CI.

**Goal:** Independent code PRs can land sequentially without an audit conflict or an audit-only CI rerun, while unread-prose shortcuts still require reviewed evidence and stale documentation evidence fails its own required gate.

**Architecture:** Keep one current record per source path and audit mode. Renew documentation records in routine code PRs; renew peer modes separately when their shortcuts are useful. Compute whole-inventory hashes from immutable current rows and matching records, without committing a mutable aggregate.

**Stack:** Node >=26, Git immutable trees, SHA-256, existing planner/checkers and GitHub Actions. **Spec:** the design below. Starting inspection: `dca4ab55e184e88b73e3e2c3c01964bcdbbacf9a`; reconcile D571 planner changes before implementation.

## Evidence and choice

The [measured history](../../backlog/ci-audit-conflicts.md) classifies 21 of the latest 30 repeated-branch head transitions as audit-conflict-only: 19 conflict only in the JSON, two also conflict in renewal notes. Nine are not attributed solely to the audit. These are new runs after changed heads, not repeated attempts of one GitHub run. The report gives the method, exact revisions and run links.

The implementation currently hashes ordered Git tree rows, including path, mode, type and object ID (`scripts/ci-input-audit.mjs:86-143`). All modes exclude the shared policy. Documentation alone excludes regular unread prose; identity and gateway exclude their own two targets; lock excludes lock bytes and separately projects workspace manifests. In particular, peer modes pin `docs/backlog.md`. Mixed-doc planning requires both documentation audits and all four renewed head modes when removing the accompanying policy (`scripts/ci-plan.mjs:13-36`); it deliberately tolerates stale base peers. Required freshness runs in root shard 1 and the script job (`.github/workflows/ci.yml:78,131`). Lock selection independently audits both trees before comparing graphs (`scripts/ci-lock-selection.mjs:6-21`). These are source findings, not execution receipts.

| Alternative | Assessment |
| --- | --- |
| Append-only, content-addressed variants per path | Independent variants, including backlog variants, avoid evidence-file conflicts. However, unioning branch evidence does not review the new combined backlog bytes. Exact peer matching must still reject that merge. Retaining every old variant also admits a previously reviewed path state automatically, potentially in a new reader context. Tombstones and retention/revocation add policy. Reject for this slice: more authority and storage than necessary. |
| **Current per-path records; less frequent peer renewal** | Choose this. Routine PRs update only docs records, which exclude regular backlog prose already. Independent source paths have independent evidence files. Stale peers retain full work; no peer prose hash needs updating merely to satisfy the documentation gate. This sacrifices shortcut availability rather than reader protection. |
| CI-hosted explicit review evidence | Could work only with authenticated, revision-bound review, complete path/deletion coverage, retained immutable evidence and unavailable-service fallback. Computing hashes in CI alone proves no review. Reject the new service/trust/lifecycle machinery when local records suffice. |

## Invariants and deliberate v2 semantics

Keep all v1 behavior, fixtures and assertions. Never turn a v1 policy with `version: 2` into valid evidence. Keep existing path allowlists, pinned documents, script targets/caller checks, manifest/lock graph rules, receipt certificates, saved fixtures, strict summary and main-push workloads. No automatic renewal in CI, merge driver, global Git change, provider/customer action or new prose exemption.

V2 changes the review unit from one entire inventory to one current path state. Independently reviewed path updates may combine without a new aggregate certificate. That is a deliberate semantic change: an unseen combination can pass although neither branch reviewed the entire combined tree. It preserves exact current input coverage, but does not prove arbitrary cross-file interactions safe. You still inspect changed readers, directory scans, generated programs, imports, subprocesses, install hooks and their effects on exemptions before renewal. A reader that starts consuming exempt prose needs a policy/test change before renewal. Full main CI and the existing merge review remain necessary. The fresh-context reviewer must explicitly accept this compositional review boundary; exact whole-tree reapproval after every merge would recreate the audit-only rerun requirement.

Unlike append-only variants, a historical present record is not an alternative authorization. Reverting to an older path state leaves its current record stale until explicit review and renewal. Combining disjoint records does not authorize a third, merged state of a shared source file. Source conflicts remain source conflicts. Before the second landing, inspect the combined reader changes against exemptions even when source paths are disjoint; this review need not regenerate already matching records or rerun the unchanged reviewed head.

Routine code PRs renew **docs only**. This does not certify identity, gateway or lock peers. An all-mode check may correctly fail on stale peers while the required docs gate passes and full CI runs. Peer renewal is an explicit, separately reviewed operation; do not add it to every code PR or require all modes current for admission to full CI. If a peer renewal overlaps another PR's prose, accept full work rather than regenerating peer evidence just to obtain a shortcut.

## Storage, completeness and exclusions

Retain `scripts/ci-input-audit.json` as frozen v1 evidence after activation. Add the regular blob `scripts/ci-input-audit-v2.json` containing exactly `{"version":2}` plus a final newline. Its presence selects v2. Unknown/malformed v2 evidence never falls back to v1. Records without the descriptor are invalid, not implicit activation. Historical trees before activation, with complete history and neither v2 marker nor records, continue through the strict v1 reader; removing all v2 metadata in later ancestry cannot renew v1 authority; stale/missing v1 bases remain conservative even with a valid v2 head.

Store records at `scripts/ci-input-audit.d/<mode>/<sha256(UTF-8 path)>.json`, with modes exactly `docs`, `identity`, `gateway`, `lock`. Serialize records with `JSON.stringify` in field order `version`, `mode`, `path`, `state`, then the additional fields in table order, followed by one newline. Each object has exactly those fields:

| State | Additional fields and meaning |
| --- | --- |
| `present` | `gitMode`, `gitType`, `objectId`: exact current included Git row, with six-digit mode, `blob`/`commit` and lowercase 40-hex object ID. |
| `manifest` | `sha256`: lowercase 64-hex digest of the current lock-mode manifest projection. Valid only for a regular workspace manifest in lock mode. |
| `absent` | `previousRevision`: immutable 40-hex ancestor commit containing a valid, non-absent v2 record for this mode/path which matches that tree's input. An explicit tombstone records removal from this mode's inventory, including a transition into its existing exemption. |

A tombstone means absent from the **mode inventory**, not necessarily absent from the filesystem. For example, executable Markdown becoming regular unread prose removes a docs input. That transition must be reviewed; subsequent ordinary edits/deletion of that prose need no docs renewal. Required owning targets, lockfile and manifests still undergo their separate regular-file checks; a tombstone cannot satisfy them.

Reject duplicate decoded JSON keys, missing/extra fields, unsupported modes/versions/states, wrong types/digests, noncanonical serialization, mismatched filename/path/mode, duplicate logical paths and unroundtrippable path bytes. Verify decoded metadata bytes against their Git blob IDs so invalid UTF-8 cannot impersonate replacement characters. Keep the v1 policy blob fixed to its first activation value. Treat source paths as opaque Git paths; retain spaces/newlines and literal backslashes without joining them to output paths. Reject NUL, absolute paths and dot traversal. `unreadMarkdown` retains its existing backslash and path exclusions. Record names are hashes, never source paths.

Read a complete NUL-terminated tree; reject malformed/truncated/duplicate entries. Validate every metadata blob and its container layout, even when checking only docs. Metadata must be `100644 blob`; reject executable files, links, gitlinks, unknown files/subdirectories or extra encodings under the record root. Exclude only the descriptor, frozen schema-valid v1 policy and validated record blobs from v2 fingerprints. Arbitrary content under the directory is not an exemption. Audit programs/tests and other files with similar names remain ordinary inputs.

For a selected mode, independently enumerate current included source rows using exactly the existing rules, then compare them with its complete record map. Every current row needs one matching record. Every retained record needs its current matching row/projection or a valid tombstone; an extra `present` record for a missing input fails. Unknown additions, changed modes/types/object IDs, deletion without a tombstone, and an unreviewed rename fail. A rename is deletion plus addition; never trust Git rename detection. For v2 commit checks, collect the union of canonical record filenames introduced anywhere in the reachable v2 ancestry through its first activation, and require the current tree to retain every name. Removing source plus record in one commit and adding an unrelated child, or merging that sequence, must still fail. Restoring a missing record repairs this retention condition; a past deletion alone is not a permanent failure. Include merged ancestry, and do not let a temporarily missing descriptor reset the history boundary. Use complete Git history and batched path-history reads, not a whole-inventory audit for every ancestor. Initial activation seeds the complete current tree; new source paths add records. Staged generation uses retained names from HEAD plus its staged records. Missing or truncated history or tombstone proof fails conservatively. The dispatcher validates the referenced prior record against that revision's path projection without recursively auditing its whole inventory. For a new or invalid tombstone, choose the first matching ancestor already shared with the target branch. Resolve `origin/main`, `origin/master`, local `main` or local `master` in that order, take its merge base with HEAD, and search that base with `git rev-list --topo-order`. Branch-only commits disappear on squash or rebase and cannot be proof anchors. Validate only the referenced prior path and record, not that ancestor’s complete inventory. Existing invalid tombstones are repaired rather than copied. No matching target ancestor means generation refuses before writing; consolidate branch-only additions and removals before renewal. This conservative refusal preserves ancestry authority without adding a new record state or trusting unreachable objects.

Hash the actual current included raw rows in their original Git order, and independently reconstruct the same ordered rows from the matched records. Require equality; do not hash a list supplied by the evidence. Report the current digest, but never store a tree-wide digest or mutable membership list. Manifest projections are compared separately, as today. Tombstones remain at their canonical path and contribute no current row.

| Mode | V2 projection, unchanged from v1 except validated metadata storage |
| --- | --- |
| docs | Omit only `100644 blob` root/`docs/` unread Markdown. Pin receipts, package Markdown, contract, cost model, executable Markdown, links and gitlinks. |
| identity | Omit only `scripts/identity-upstream.mjs` and `scripts/identity-upstream.test.mjs`; require both regular. Pin all prose and gateway inputs. |
| gateway | Omit only `scripts/verify-gateway-reconnection-receipt.mjs` and its test; require both regular. Pin prose, identity and `scripts/gateway-reconnection-receipt.mjs`. |
| lock | Require regular lockfile; omit its bytes. Project every current workspace manifest by validating/removing only `dependencies`, `devDependencies`, `optionalDependencies`, `peerDependencies`. Retain all remaining fields, sort only top-level keys using today's `localeCompare(..., 'en')`, then hash `JSON.stringify`. Do not recursively normalize nested metadata. Root manifest remains a full row; prose remains pinned. |

Discover complete workspace membership separately in each immutable tree with today's workspace-layout, unique-name and test-command validation. Dependency-only manifest edits keep lock projections stable, but remain full-byte changes for docs/identity/gateway. New/removed manifests, license/scripts/exports/hooks and nested metadata ordering must not silently disappear. Historical nine-manifest receipt evidence remains untouched and cannot authorize current membership.
