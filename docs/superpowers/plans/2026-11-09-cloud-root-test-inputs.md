# D613: stop unrelated slow root tests on package PRs

**Ask and authority.** Owner, Lane I `questions.md`, 9 November 21:45: “Find which root tests read the changed files and run only those on a pull request; the rest go to the nightly.” At 21:35: “Nothing a change actually needs stops running; anything moved off PRs still runs nightly.” Those instructions authorise planning, not this mechanism. Execute inline only after the watcher approves. The first Claude read rejected the pinned closure table; this revision uses its simpler omission list.

**First usable cut.** Audit at most twenty slow root test files and omit only those with no live reader of any package's source/tests. Eligible PRs change regular files only in existing `packages/*/{src,test}/` or `apps/*/{src,test}/`, optionally with ordinary root/docs prose under the existing documentation policy. New packages, manifests, migrations, package READMEs, shared inputs and main ranges retain today's root work. The retained 80-PR list has nine path-shape candidates, including #1121 and #1122; immutable file/prose checks may reduce that count. This is a bounded first cut, not complete root ownership.

**Evidence and target.** The actual command discovers 148 direct `scripts/ci-*.test.mjs` files and four explicit files: 152 total. Its root jobs used 24.63 / 25.10 job-minutes in the registration / portal examples. Retained TAP logs attribute 1,072 successful top-level cases in each example to unique literal names in historical source files. The slowest candidates include package-revision fixture tests, dependency fixtures, lock selection and storage-readiness diagnostics. These are case-time contributions, not file elapsed times: dynamic names and startup remain unattributed, and two file workers overlap. Audit slowest-first and record the actual reader paths and attributed times outside the repository. Aim to remove at least five root job-minutes on a healthy natural eligible PR; if the audit cannot support that target within the budget, return to the watcher with the smaller measured opportunity before building.

**Mechanism.** A short plain list of omitted test paths lives in new `scripts/ci-root-selection.mjs`. No blob pins, renewal records, JavaScript parser or new evidence subsystem. Unknown/new tests run by default. Trace each candidate's imports, helpers, copied inputs, directory reads and children; synthetic package names alone do not establish live readers. Changes to root readers require ordinary review of this list. Package allocation, registration discovery, database receipt and other actual package readers stay. The selector discovers all four explicit files as well as the direct glob, then returns a sorted nonempty retained list. There is no empty-overall-selection branch.

The selected command uses the list and shard; an empty individual partition is explicit. A second workflow step keeps the literal legacy command when the output is absent, so older heads keep full work. No live older-head experiment is needed for this cut. Full/nightly runs keep every root test and existing suite; cost scheduling is separate.
